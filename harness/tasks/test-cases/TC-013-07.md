## Preconditions

- The implementation must document a concrete UTF-8 file-path loader/validation command and its success/error interface.
- Invoke that actual command in subprocesses using temporary fictional files; deny outbound network access and instrument provider/device-write entry points.
- Proposed tests are local and require no hardware, HA endpoint or credentials.

## Steps

1. Invoke the documented command with explicit paths to the public fixture and the renamed/moved copy from TC-013-04, including a path containing spaces and Unicode names in file contents.
2. Provide malformed JSON, unsupported schema_version, an unknown nested field, a dangling reference, an unreadable/missing file and invalid UTF-8 bytes, each in isolation.
3. Compare exit outcomes and diagnostics across repeated invocations; confirm validation errors identify the file and field path, and parse/I/O errors identify the file and cause without fabricating a successful inventory.
4. Verify zero network/provider/device-write calls and unchanged input file contents on every outcome.
5. Execute the linked TC suite plus applicable package lint/type checks and `bash scripts/check.sh`; record results tied to the tested implementation commit.

## Expected Results

- AC6: valid explicit UTF-8 files succeed; parse/version/reference/I/O/encoding failures produce actionable diagnostics and unsuccessful command outcomes. Error locations use a field path where parsed structure exists.
- The loader works offline, preserves source files and returns no successful inventory on error.
- AC7: every TC records command, tested commit, runtime/dependency environment, case counts, pass/fail/skip and evidence location. All required checks pass before implementation approval; skips/missing modules cannot establish runtime acceptance.
- TC design and governance checks alone do not justify `passing`, checking REQ acceptance boxes or marking REQ-013 done.
