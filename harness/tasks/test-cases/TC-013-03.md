## Preconditions

- Derive single-fault inventories from a known-valid baseline so the expected error is unambiguous.
- Use table-driven mutations for each envelope/object field; do not assert validation-library-specific prose.

## Steps

1. Remove required fields; provide null or wrong scalar/list/object types. Test unsupported schema versions, including a string and boolean instead of integer 1; use boolean/string/fractional floor levels.
2. Test empty IDs, uppercase/leading-digit/space IDs and IDs longer than 64 characters; verify one-character, 64-character, hyphen and underscore IDs are accepted.
3. Duplicate IDs within each record kind and across different kinds, including a Home ID reused by another object.
4. Test blank/untrimmed names, blank or duplicate aliases, duplicate label references, undeclared labels (including `childen`), unknown residence/area types, and empty/duplicate/unknown group area types.
5. Set each Floor/Area/Device home_id to an absent or different Home; reference missing floors/areas and wrong-kind IDs.
6. Repeat each rejected input and compare field paths; include a nested list-item error and then validate an unchanged baseline.

## Expected Results

- AC3: every invalid mutation fails deterministically with the offending field/list-item path. No string/number/boolean coercion, typo correction, deduplication or reference repair occurs.
- IDs are globally unique across the six canonical record kinds. Wrong-home and dangling containment are rejected even when other fields are valid.
- Valid boundary IDs and the unchanged baseline pass; invalid-input checks cannot be satisfied by a validator that rejects everything.
