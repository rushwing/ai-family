## Preconditions

- Load the public fixture; use separate augmented copies for overlapping groups, multi-label areas, device labels and unassigned devices.
- Compare complete sorted ID lists against explicit expected values, not only lengths.

## Steps

1. Resolve `area_ids: [area-bedroom-02]`; expect that area and `device-bedroom-light-02` only. Select Living Room separately and expect no devices.
2. Resolve group `resting`; expect bedroom areas 01/02/03 and their three lights. Add `label_ids: [children]`; expect bedroom 02 and its light only.
3. Resolve `daily_life` and `resting` together; expect the two living/dining areas and three bedrooms, with exactly the three bedroom lights.
4. Add a group overlapping `resting`; request both groups and permute input inventory and selector ordering.
5. Apply two registered labels to only one selected area; request both labels and distinguish all-label intersection from any-label union. Place the same labels on a device outside that area.
6. Resolve unused `studio` and `storage_utility` groups; repeat with a registered label matching no selected area and with an explicit empty label list.
7. Include a device with null area_id and an area with null floor_id; resolve the latter explicitly.

## Expected Results

- AC5: exact output lists are sorted and unique, invariant under input ordering and group overlap. Device IDs come only from selected area assignments.
- Label filters require all requested area labels; device labels never broaden area selection. Empty label filters impose no additional restriction.
- Empty groups/no matching labels yield both output lists empty without fallback. Unassigned devices stay excluded, while areas with null floor_id remain selectable.
