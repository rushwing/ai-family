   with JWT/test metadata and user-source two-phase confirmation.
2. Omit the tool wrapper or durable confirmation store: both issuance and action
   fail unavailable with zero handler calls. An injected generic Goal executor
   cannot enable the home tool.
3. Ordinary bearer, Agent prepare, missing/changed/replayed proof or confirmation,
   unauthorized identity/role/member/home/device policy: zero handler calls.
4. Issue a valid exact-payload confirmation on one app, then execute once on
   another with the shared database. Reconstructed apps reject proof and token
   replay. Changing parameters fails without consuming the valid original.
5. Revoke the current resource policy after confirmation: execution is denied
   before token consumption. Policy is rechecked at the tool as well.
6. Fail database access: return fixed redacted unavailable responses and never
   fall back to process memory. Persisted-token consumption does not promise
   task completion or physical convergence.
