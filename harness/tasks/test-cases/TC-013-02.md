## Preconditions

- Start with a valid inventory containing assigned and unassigned relationships.
- Build fresh copies for each mutation; record IDs and references before changes.

## Steps

1. Add floors at levels -1, 0 and 1, plus another negative and positive integer; vary floor names independently of levels.
2. Rename Home, Floor, Area, Device, Label and Area-group display names; use duplicate nonblank display names for distinct records.
3. Move an area between floors and set its floor to null; move a device between areas and set its area to null.
4. Resolve explicit areas and groups after each move; inspect each device's derived floor through its current area.
5. Rename, add and remove groups and change their nonempty area-type membership using the supported vocabulary; include unused groups.
6. Rename label display names while retaining registered label IDs and selector references.

## Expected Results

- AC1–AC3: identities remain unchanged; references continue to address the original records. Duplicate display names are allowed and never used as target keys.
- Integer floor levels have no -1/0/1-only restriction; null floor/area relationships validate. A device derives its floor through its area, with no stale direct floor assignment.
- AC2/AC5: edited groups drive selection immediately, unused groups resolve empty, and label display names do not change ID-based matching. Group edits do not create scenes, workflows or permissions.
