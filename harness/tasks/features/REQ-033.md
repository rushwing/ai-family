## API and boundaries

Add home_device_fabric.ha_capabilities.HACapabilityInferrer with keyword-only
provider_instance_id, infer(inventory=..., bindings=..., discovery=...), and
HACapabilityError. Construction validates the canonical instance alias and
explicitly loads a detached accepted packaged revision-1 initial catalogue.
Only this fixed package resource is read; import/infer perform no I/O, clock,
environment, randomness, logging, LLM call or provider operation.

Inputs are plain JSON trees under REQ-032's limits: 32 container levels,
200000 nodes/keys, 16 MiB encoded JSON, finite numbers, valid UTF-8, integers
at most 4096 bits, no container aliases/cycles. Discovery has exactly four
components and the accepted complete structural validation, including omitted
rows. Inventory and BindingCollection pass accepted factories/reference checks.
Only HA bindings matching the configured instance are considered. Other
providers/instances are structurally validated but omitted. Each selected entity
belongs to exactly one selected binding. Its enabled registry record must exist,
have the binding's device_registry_id (including null for standalone), and, for
grouped entities, reference an enabled present device registry row. Inconsistent
bindings reject the entire call; no partial result. These checks establish
structure, not source authenticity, freshness, permission or snapshot atomicity.

## Frozen rules version 1

Rules inspect exact, case-sensitive entity domain and current-state attributes;
entity IDs must match ASCII [a-z0-9_]+\.[a-z0-9_]+. Rules do not parse
names, registry labels or current numeric observation values.
Missing state means unsupported. Unknown/unavailable state with sufficient
metadata can still describe a capability; it proves no availability or value.
No conversions, coercion, inferred services or guessed features occur.

| HA metadata | Canonical descriptor | Property source | Action mapping |
|---|---|---|---|
| switch domain | home.switchable v1 | state → is_on | set_on: is_on true → switch.turn_on; false → switch.turn_off; empty service data |
| cover domain and exact nonnegative int supported_features ≤2147483647 with bit 4 set | home.positionable v1 | current_position attribute → position_percent | set_position → cover.set_cover_position; position_percent → position |
| sensor, device_class temperature, unit °C | home.temperature_sensor v1 | state → temperature_c | none |
| sensor, device_class humidity, unit % | home.humidity_sensor v1 | state → relative_humidity_percent | none |
| sensor, device_class power, unit W | home.power_meter v1 | state → power_w | none |
| sensor, device_class battery, unit % | home.battery_powered v1 | state → battery_percent | none |

Each emitted capability contains the unchanged accepted descriptor, one explicit
HA entity/instance mapping, property source mapping, and mappings for exactly
the descriptor's actions. The descriptor supplies strict parameter schemas and
risk/timeout/idempotency/completion semantics. Mappings describe future
dispatch only; they neither execute nor authorize it. Missing current_position
does not fabricate a value. Measurement parsing/State integration remain separate.

Within a canonical Device, multiple eligible entities for the same capability
are ambiguous: omit that whole capability and count all its eligible entities
as ambiguous. Never choose the first/last entity, aggregate, or split identity.
Other unambiguous capability types on the Device remain. Unmatched/unsupported
entities count as unsupported; unbound discovery rows never advertise anything.
No eligible capability means the Device remains in the output with an empty
capabilities list. Sort Devices by canonical identity and capabilities by ID.
Each call is a fresh independent projection; removal changes this result only.

## Output, limits and errors

infer returns a private immutable result with for_adapter() exporting detached
JSON {rules_version:1, devices:[{home_id,device_id,capabilities:[...]}]}.
to_redacted_dict returns rules_version and only device/capability/unsupported/
ambiguous integer counts. Constant repr, no pickle/copy/deepcopy; immutable
inferrer/result reject reinitialization. Raw exports contain provider IDs and
remain inside trusted adapter code. No raw state values or attributes are copied
to outputs. Public errors have finite fixed codes invalid_configuration,
invalid_inventory, invalid_bindings, invalid_discovery, input_limit,
invalid_projection; no submitted values or retained underlying exception chains.
Process-control exceptions propagate. Private introspection/traceback locals
are outside supported diagnostics. Bound output to the same JSON limits.
