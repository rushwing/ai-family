## API and transport

Add home_device_fabric.ha_discovery.HARegistryDiscoveryClient(configuration, *,
max_response_bytes=262144, max_records=2048), HADiscoverySnapshot and
HADiscoveryError. Exact HAConfiguration is required; construction performs no I/O.
Byte limit is an exact integer 4096..4194304; records limit 1..10000. No ambient
credentials, arbitrary command, URL, callback, device action or public route.

await client.discover() owns a fresh authenticated /api/websocket connection
and exactly four serial read-only commands, with IDs 1..4:
config/device_registry/list, config/entity_registry/list,
config/area_registry/list, get_states. Authentication must finish before any
command. Reuse accepted no-redirect, no-proxy, explicit TLS trust and disabled
wire-logger policy without modifying the accepted lifecycle or REST API.
The WebSocket interface supports all four inputs; no REST fallback is needed.

One configuration.request_timeout_ms budget covers connection, authentication,
all commands, decoding and validation; it is never reset per stage. Cleanup has
at most one additional second and aborts if graceful close fails. Success also
requires completion before the operation deadline. No automatic retry or
reconnect; the owner can explicitly invoke discovery again with a fresh socket.

The client is bound to one event loop, rejects concurrent discovery as
client_busy, and rejects discovery after close as client_closed. aclose is
idempotent, closes admission, cancels in-flight work and drains owned cleanup;
cancellation of a close waiter cannot cancel its owned drain. Cancelling discover
also drains the operation before propagating CancelledError, including repeated
cancellation. Close before/after/in-flight discovery is supported; cancellation
and explicit close cannot publish a successful snapshot. Async context manager
exit closes the client. Reinitialization and raw serialization/copy are refused.

## Validation and completeness

Frames must be text, UTF-8 byte-bounded, strict JSON with unique object keys,
finite numbers and at most 32 container levels. The decoder rejects binary,
invalid/non-object JSON, duplicate keys, non-finite constants/exponents, invalid
Unicode, malformed envelopes, wrong or boolean IDs and unsolicited events.
Every result requires type=result, matching exact integer ID and exact boolean
success. Failure error.code is a string: unauthorized/not_allowed maps to
permission_denied, unknown_command to unsupported_command, other codes to
command_failed. Malformed errors fail invalid_response. Peer messages are never
copied into errors. A failed component stops discovery, without later commands
or a snapshot; successful earlier reads appear only as finite completed labels.

Each successful result is a list of at most max_records plain objects, with
unique nonempty provider IDs of at most 512 characters within that component:
devices.id, entities.entity_id, areas.area_id, states.entity_id. Areas also
require nonempty name <=512 chars; states require state string <=4096 chars
and attributes object. Optional device/area references, when present, are null
or nonempty strings <=512 chars. Extra provider fields are preserved privately,
without interpreting them as canonical IDs, capabilities or actions. Missing
references, disabled entities and registry/state-set differences are retained
for the later mapper, not reconciled here. Empty successful lists are valid;
permission/unsupported/partial failures are never converted into empty success.

Complete means four validated successful responses for this credential's view,
not an atomic HA-wide snapshot, global permission proof or freshness guarantee.
In particular get_states can be permission-filtered by HA without an explicit
error. Serial reads may race registry changes. There is no epoch, canonical
mapping, provider binding creation or current-state-store publication here.

## Data and diagnostic boundary

The immutable snapshot exposes to_redacted_dict() with complete:true and only
per-component counts. Trusted adapter code explicitly calls for_mapping() to
obtain detached devices/entities/areas/states JSON. Provider records may contain
private identifiers, labels and attributes; never send this accessor to logs,
agents or northbound users. Repr is constant, copies/raw serialization refused.
Payloads are never retained on the client after the operation.

HADiscoveryError has only validated finite code, stage and completed labels;
to_dict/str/repr contain no endpoint, credential, provider ID or peer text.
Codes: auth_failed, permission_denied, unsupported_command, command_failed,
invalid_response, response_limit, timeout, transport_failed, internal_error,
cleanup_failed, client_busy, client_closed. Stages: operation, auth, devices,
entities, areas, states, cleanup. Raw exception context is discarded before
raising; no wire/body logs. Process-control exceptions propagate after cleanup.
Private introspection, process memory and traceback frame locals are outside
the diagnostic boundary. A first acquisition failure is retained if cleanup
also fails; cleanup failure after otherwise successful acquisition rejects it.
