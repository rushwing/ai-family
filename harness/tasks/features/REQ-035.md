## Contract and scope

Create the Python/FastAPI package in apps/home-intelligence-api. A fail-closed
app factory requires an accepted HomeQueryService, explicit token verifier,
server-owned millisecond clock and finite freshness threshold. No default live
inventory, grants, credentials or demo app is served.

Retain GET /api/twin/snapshot and GET /api/devices/{device_id}; add GET
/api/home, /api/areas and /api/devices (optional area_id). All require home_id
as an explicit selector. Snapshot returns home, areas, devices and one atomic
whole-home StateView capture. Device detail returns canonical device, StateView
and capability metadata envelope. Separate projections are not a multi-call
transaction. There are no unprefixed route aliases or write/task endpoints.
The reviewed proposal is recorded in ADR-017; existing ADR-008/010/016 remain
the identity/governance/provider authorities. Generated OpenAPI is the schema.

Verify RS256 tokens using explicit trusted issuer, audience and pinned RSA
public keys keyed by kid; reject missing/expired/invalid signatures, wrong
issuer/audience, unknown keys and malformed claims. Require exp, iat, sub,
family_member_id and one unambiguous platform role, preserving the gateway's
admin/adult/kid and legacy-role mapping conventions. Ignore token-supplied
URLs and requested identity overrides. Key rotation/revocation uses a newly
composed app; no network discovery/JWKS or mutable global authentication state.
The home selector never grants access: construct context from verified
sub/member/role plus selector, and let the accepted service check its exact
subject/member/home/role grant before lookup or selector validation. The
trusted composition owner supplies grants, refreshes state and rebuilds the
service/app when grants or metadata change. Existing grants are home scoped;
no per-device deny policy is invented.

Success is HTTP 200 with status=found and typed data, including offline, stale
and uninitialized state without invented zero/false values. Missing device or
area filter is HTTP 404 with status=not_found,data=null. Known empty area is
200 with an empty list. Unknown capability metadata remains uninitialized;
known empty remains found with []. Errors have a fixed error.code: 401
unauthenticated (WWW-Authenticate: Bearer), 403 forbidden, 400 invalid_request,
503 state_unavailable, or 500 internal_error. Authentication precedes query
validation; authorization precedes selector diagnostics. Query parameters are
strictly allowlisted; duplicate parameters, invalid IDs, caller-supplied time
or identity and request bodies on GET are rejected. Clock regression fails
with 503. All responses use Cache-Control: no-store and X-Content-Type-Options:
nosniff. Validation/server diagnostics never echo bearer tokens or household
values. OpenAPI/docs contain static schemas, not inventory. No CORS trust or
credential-forwarding defaults are added.

## Acceptance criteria

- [ ] AC1: authenticated HTTP queries return documented canonical home/area/device/snapshot projections with compatible prefixed route names and no provider mappings.
- [ ] AC2: real signed-token integration tests establish identity verification, exact caller grants, household/member/role isolation and authentication/authorization ordering; rejected reads never call a provider.
- [ ] AC3: missing, empty, unknown capabilities, offline, uninitialized, fresh/stale boundary and clock failure remain explicit; fixed error responses and no-store headers prevent household/credential disclosure.
- [ ] AC4: required API tests run with zero skips, lint/type and governance checks pass, and installed direct/sdist-derived artifacts expose the same routes and OpenAPI contract in normal/optimized Python.
