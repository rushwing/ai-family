## API and authorization boundary

Implement home_device_fabric.state_store.CurrentStateStore(*, inventories, grants).
Inventories is a list of validated canonical Inventory JSON objects with distinct
home IDs. Canonical device IDs are scoped by home. The registry is fixed for
this instance; each registered device starts at revision 0, uninitialized, with
unknown availability, no reports and no desired intent. No implicit registration.

Grants is a list of exact objects containing subject_id, family_member_id,
home_id, role and access (read or write); context fields use the accepted
RequesterContext parser. Each grant must reference a configured home and a
unique (subject, member, home, role) tuple. A write grant includes reads; kid
write grants are rejected. Role alone grants nothing. Empty registries/grants
are valid and fail closed. Inputs are detached; repr is constant and raw store
pickle/copy/deepcopy are refused. Errors have finite codes and fixed tuple paths,
with underlying canonical diagnostics suppressed.

Each operation accepts context JSON (subject_id, family_member_id, home_id, role)
from a trusted authenticated caller. This helper does not authenticate a token
or prove that a supplied subject is genuine. Northbound integration must derive
context from verified identity, never arbitrary tool/agent parameters. Validate
context shape, then require exact grant identity and requested home match before
device lookup, payload validation, revision or freshness checks. Denied access
returns fixed forbidden at (scope,), with no existence/payload leak or mutation.
The API exposes no enumeration, cross-home aggregate or network route.

## Read, replace and freshness

read(context, *, home_id, device_id, now_ms, max_age_ms) returns immutable
StateView or StateNotFound. A valid unknown device in an authorized home returns
StateNotFound; malformed device IDs fail invalid_identifier. Denial precedes
that distinction. StateView contains a frozen DeviceState, revision,
updated_at_ms and freshness (uninitialized, fresh, stale); to_dict is detached.

put(context, *, home_id, device_id, state, expected_revision, now_ms) requires
write access and exact nonnegative integer expected_revision. State must be a
complete validated canonical DeviceState matching home/device. Unknown devices
return StateNotFound without creation. Compare-and-swap mismatch raises
revision_conflict. An admitted put increments the per-device revision exactly
once, including an identical full replacement; failed operations change nothing.
This is owner-authorized full-snapshot replacement, not normalized-delta apply.
Do not pass HAEventNormalizer deltas here as stored snapshots: HI-S017 will merge
observed members with apply_state_update and preserve desired intent/history.
No physical-device writes or ACK-derived convergence occurs.

now_ms and max_age_ms are caller-supplied exact nonnegative integers in one
monotonic elapsed-time domain per store lifetime. No ambient clock is read.
A read/write with now_ms earlier than that device's last update fails
clock_regression. Freshness is snapshot ingestion age, not a claim that every
property is current or a device is online. Initialized snapshot is fresh iff
now_ms - updated_at_ms <= max_age_ms; otherwise stale. Availability and canonical
observation timestamps are unchanged. Uninitialized device has no update time
and remains uninitialized regardless of TTL. Revision/time reset on a new store;
these local cache revisions are not source ordering, durable cursors or epochs.

All publication and CAS operations are synchronized within the process. Snapshot
validation is completed before publication. Returned records remain usable
without a lock and cannot mutate the store. No multi-process consistency claim.

## Restart reconstruction

rebuild(context, *, home_id, states, now_ms) requires write access and a complete
canonical StateCollection JSON object for exactly all registered devices in that
home. It is allowed only while every device in that home has revision 0; any put
or completed rebuild makes further rebuild fail already_initialized. Validate
all identities, duplicates and states first. Provider reconstruction cannot
supply desired_state: require None, since durable task/intent restoration is a
separate owner concern. One atomic commit publishes every device at revision 1
and the supplied update time. Empty configured homes may rebuild as empty once.
Malformed/partial/duplicate/cross-home collections and concurrent losers leave
all state unchanged. Other homes remain independent.

Restart creates a new uninitialized store from trusted registry/grants; the
adapter fetches and maps a fresh provider snapshot, then supplies the complete
canonical collection. This interface performs no fetch, provider mapping,
epoch allocation, snapshot/live-event reconciliation or persistence. Never
restore desired intent or source ordering from local cache revisions.
