## Background and outcome

[HI-S004](../../../docs/product/home-intelligence/requirements/stories/HI-S004.md)
combines accepted bounded REST (REQ-023) and authenticated WebSocket lifecycle
(REQ-024). A successful REST request does not imply an available event channel;
an authenticated socket does not imply reachable REST, subscriptions or healthy
physical devices. Callers need separate finite diagnostics and conservative
combined readiness without holding credentials or raw upstream responses.

## API and scope

Add home_device_fabric.ha_health with HAHealthMonitor and HAIntegrationHealth.
HAHealthMonitor(configuration, *, observation_interval_ms=1000) accepts exactly
HAConfiguration and an exact int interval in 1..60000 ms; invalid values produce
fixed errors before client construction or I/O. It owns one new HARestClient
and HAWebSocketClient for that configuration. Construction performs no I/O.
Public operations: async run(), async aclose(), synchronous health(). One
single-use lifecycle on one event loop; repeated run or run after close and
cross-loop async use reject before new I/O. No externally supplied transport,
callback, endpoint, credential or correlation override.

run starts one WebSocket lifecycle, one nonoverlapping periodic REST probe and
one periodic sampler. Probe /api/config through the existing runtime_info API;
discard version and raw errors. Use an adapter-internal valid correlation ID
which cannot contain the configured credential (including one-character tokens).
The monitor does not restart terminal WebSocket clients or extend their finite
reconnect budget. A terminal WebSocket result remains visible while REST
observations continue until explicit shutdown.

HAIntegrationHealth is a frozen slots value with rest_state (unknown, reachable,
unreachable, auth_failed), rest_reason (None or a finite REST category plus
stale/internal_error), websocket (an exact immutable HAConnectionHealth), closed
(bool) and sequence (nonnegative exact int). to_dict returns detached data only,
including state, rest_reachable (None/True/False), event_stream_connected and
the component fields. No endpoint, token, version, upstream text or raw exception
is retained. Initial rest_state is unknown, socket disconnected, sequence zero.

Combined state priority: closed; either component auth_failed; socket reconnecting;
connected only when REST is freshly reachable and socket connected; otherwise
disconnected. event_stream_connected means authenticated WebSocket transport,
not confirmed subscription or entity freshness. In closed health it is false and
rest_reachable is None; component fields retain their last observed diagnostics.
Sequence grows only when supported snapshot fields change. Returned snapshots
are stable immutable values; mutating an exported dict cannot alter them.

## Observation timing and freshness

The configured interval bounds polling of already-published WebSocket transitions
and REST probe admission cadence, subject to event-loop scheduling. Probe at
startup and then once per interval measured from each probe start; never overlap
or queue catch-up probes. REST results publish immediately on completion.
If a previously successful REST observation reaches one interval of age while a
new result is unavailable, the independent sampler expires it to unknown/stale.
A pending/slow probe cannot preserve a false connected state indefinitely.
Failures remain visible until a newer result; auth failure takes precedence over
reconnecting. Recovery publishes after a fresh successful read and socket health
observation, within the next sampler interval once those observations exist.

Network detection itself includes the existing configured REST request deadline
and bounded cleanup; this is not an external-network hard real-time SLO. A
scheduler stall cannot be detected while the event loop is stopped. health()
refreshes expiry and socket observation synchronously when running, without I/O,
so the first read after a scheduling gap cannot return expired REST success.
Tests use controlled monotonic time and gates, rather than short wall-clock
request-count assumptions. The interval is adapter scheduling policy and does
not extend HAConfiguration's versioned settings schema.

## Shutdown, cancellation and privacy

aclose permanently closes admission and freezes a closed snapshot before its
first await, cancels owned workers once and drains REST/socket cleanup. Repeated
and concurrent close is idempotent. Cancelling a close waiter propagates while
owned closure continues; cancelling run drains closure before propagating.
Close before run closes the unused clients without starting network work.
Late results or cancellation-resistant test peers cannot change closed snapshots.
Child process-control BaseExceptions propagate to run after cleanup; ordinary
unexpected worker failures produce a fixed health_monitor_failed error after
context is discarded. Close does not replay worker errors or claim live-service
cleanup certification. Client repr and serialization refuse credential exposure.
No unbounded histories, user callbacks, raw exception storage or monitoring logs.

persistent monitoring, live HA certification, Feature/Stage completion and
