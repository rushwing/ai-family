## Context and scope

REQ-037 validates canonical semantics. REQ-014 binds canonical devices to
provider resources; REQ-033 supplies private version-1 descriptor/mapping
projections. This slice joins those accepted boundaries without dispatch.

`home_device_fabric.action_resolution.ActionResolver` is an immutable one-home,
one-selected-HA-instance service constructed with raw plain JSON
`registered_inventory`, `bindings`, `capability_projection`, canonical alias
`provider_instance_id`, and optional `max_input_bytes` (default 65536, exact
positive int at most 16777216). Construction validates Inventory and
BindingCollection references, bounded JSON, and the REQ-033 projection envelope
(`rules_version: 1`, `devices`), with each device record exactly
`home_id/device_id/capabilities` and each entry exactly
`descriptor/provider_mapping`. Descriptor catalogues use accepted schema
factories, forbid duplicate identity/revision and unknown/duplicate devices.
Partial device metadata is permitted and has REQ-037 missing semantics.
`provider_mapping` may be null or an object: its operation semantics are checked
only after request validation, so an unusable private map never enables dispatch.
Malformed configuration raises only `ActionResolutionError("invalid_configuration")`
outside the underlying handler, with no original exception chain. Construction
explicitly reads the packaged initial capability catalogue; resolution performs
no I/O. Caller configuration and all exports are detached.

The package-internal REQ-032 helpers `_json` and `_canonical` provide bounded
plain-JSON validation/canonical encoding and alias validation. They remain
private, unchanged, and changes require checking their resolver consumer.

## Resolution contract

`resolve(request)` accepts raw canonical ActionRequest JSON, never a prevalidated
result or typed record. It reuses a private ActionValidator constructed from the
projection descriptors, with the exact configured byte budget. REQ-037 failure
codes/order are preserved before binding/mapping lookup. It then applies:

1. No binding for the exact canonical device: `missing_binding`.
2. Binding provider is not `ha`, or its instance differs from the selected
   configured instance: `provider_mismatch`. Never choose another device,
   instance, binding or fallback provider.
3. Capability identity/revision/action must be exactly version 1
   `home.switchable/set_on` or `home.positionable/set_position` with the unchanged
   packaged descriptor: otherwise `unsupported_operation`. Read-only sensors
   are already rejected by REQ-037. No arbitrary vendor or synthesized actions.
4. Null provider map: `mapping_uninitialized`. Otherwise the entire map must
   match the REQ-033 version-1 shape, including properties and actions, provider
   and selected instance. The exact `entity_id` must be a member of this
   binding's entity_ids and match the corresponding `switch` or `cover` domain
   with ASCII `[a-z0-9_]+` entity suffix. Any mismatch or extra field is
   `invalid_provider_mapping`. Grouped devices may contain multiple entities;
   the capability selects exactly one registered entity, never the first entity.
5. `set_on({is_on: true/false})` resolves respectively to `switch.turn_on` or
   `switch.turn_off` with empty service_data. `set_position({position_percent: n})`
   resolves to `cover.set_cover_position` with `service_data: {position: n}`,
   preserving integer 0–100. No coercion, rounding, service overrides or extra
   input fields. The target is exactly `{entity_id: <registered entity>}`.

Each call returns immutable `ActionResolutionResult` with status `resolved`
or `rejected` and finite `failure_code` (null only on resolved).
`to_redacted_dict()` exports exactly status/failure_code, without canonical or
provider identities, request arguments or correlation values. `for_adapter()`
is a private trusted-adapter export of exactly status/failure_code/request/operation;
both latter fields are null on rejection. On resolution, request preserves the
canonical validated request (including idempotency_key and trace_id); operation
is exactly provider/provider_instance_id/domain/service/target/service_data.
It is a description, not a token or dispatch authority. Direct result construction
is internal typed use; only resolve() supplies checked results. Repr is constant
and pickle/copy/deepcopy are rejected for service and results. Resolution has
zero provider, network, clock/random/environment/file effects, no logging,
global mutation or caches. Independent instances and concurrent calls isolate.

Canonical schemas/API/workflow payloads remain unchanged. Provider identifiers
are available only through the explicitly private adapter export. Trusted callers
must recheck current bindings/availability and apply identity, member/device
policy, confirmation, audit and task/idempotency semantics before later dispatch;
snapshot resolution cannot establish runtime freshness or permission.
