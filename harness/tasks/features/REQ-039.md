## Context and scope

Contributes to [HI-F008](../../../docs/product/home-intelligence/requirements/features/HI-F008.md).
Provide a shared action guard entry point independently reusable by later
callers without enabling unfinished physical writes.

- Check trusted JWT identity and member/device policy before action dispatch.
  Request body identities and a caller-constructed context are not authentication.
- Require the ADR-010 user confirmation boundary for writes. Ordinary Agent
  bearer requests cannot issue their own confirmation or self-confirm.
- Reject offline, unauthorized and unsupported actions with zero provider calls;
  preserve existing kid structured/read-only restrictions.
- Before physical writes, reuse verified shared gateway persistence for durable,
  atomic, replay-safe confirmation issuance and consumption across restart and
  multiple instances. Never duplicate or bypass a missing shared implementation.
- Reuse accepted canonical request/schema validation from REQ-017/018/037.
  Provider operation descriptions from REQ-038 confer no dispatch authority.
  Later dispatch still requires current bindings/availability, durable audit
  and governed task/idempotency semantics under their owning requirements.

## Acceptance criteria

- [ ] AC1: trusted JWT identity and member/device policy are checked before action dispatch.
- [ ] AC2: writes require the ADR-010 user confirmation boundary; ordinary Agent bearer requests cannot self-confirm.
- [ ] AC3: offline, unauthorized and unsupported actions fail closed with zero provider calls; existing kid restrictions remain in effect.
- [ ] AC4: the reused shared confirmation implementation has passing evidence for durable atomic issuance/consumption and replay safety across restart and multiple instances, including user-interaction proof reuse, before physical writes are enabled.
