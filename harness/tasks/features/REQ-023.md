## Requirement Description

### Package and Public Boundary

Add an adapter-local REST module to the existing ai-family-home-device-fabric distribution. Reuse the accepted HAConfiguration, including its endpoint spelling, request_timeout_ms and explicit access_token_for_transport() boundary. Do not extend MockConfiguration, ProviderProtocol or canonical Home/State/Capability/Action envelopes for HA runtime metadata.

Proposed public API: an asynchronous HARestClient constructed from HAConfiguration, an explicit runtime_info() operation returning immutable HARuntimeInfo, and a HARestError with a finite structured code and caller-supplied correlation ID. Provide deterministic async context-manager/close behavior; opening/constructing the client does not issue a request. Names, exact shapes, correlation-ID validation and ownership of an injected test transport are settled by independent requirement review and frozen by TC design before implementation.

Use one maintained HTTP transport dependency suitable for bounded asynchronous reads. The proposed choice is HTTPX with explicit settings; no HA SDK, OAuth flow or new service is needed. Confirm dependency version bounds, Python 3.12–3.14 support, packaging and cancellation semantics during review. A test seam must exercise the production authentication, status classification and parsing paths rather than return an already parsed success object.

### Authenticated Runtime Read

For each call, send exactly one GET to configured base_url + /api/config, with Authorization: Bearer followed by the explicitly supplied credential and Accept: application/json. Preserve the configuration's endpoint contract; paths, methods, headers and destinations are not caller-configurable. There are no device writes, generic request/HA-service entry points, automatic retries or reconnect scheduling.

Disable automatic redirects, ambient proxy/environment configuration, cookie persistence and implicit credential lookup. TLS certificate/hostname verification is enabled for HTTPS; there is no public verification-disable option. HTTP remains supported because accepted configuration allows it. Never forward the credential to a redirected destination, including a same-origin redirect. Response URLs, Location, cookies, server error text and headers are not public diagnostics.

Status 200 is the only success status. Return only the required HA version as typed adapter-local runtime metadata; discard unrelated HA configuration, including location, coordinates, filesystem paths, unit settings and components. The proposed result contains version only. Validate version as a plain, nonempty, bounded printable ASCII string (maximum 128 characters), reject surrounding whitespace and a projected value containing the supplied credential or configured endpoint, and never coerce non-string values. Exact accepted version syntax is a review decision; do not infer a production HA-version certification claim from fake fixtures.

Accept a UTF-8 JSON object with a required version string. Additional fields are ignored, not retained. Reject malformed UTF-8/JSON, duplicate object keys, non-object roots, missing/wrong-type/invalid version and non-finite JSON constants. Content-Type must identify application/json, optionally with UTF-8 charset; incompatible media types/charsets fail as invalid_response. The projected result and client have supported safe inspection/serialization boundaries defined at TC design; no object retains the raw response as an exported diagnostic.

### Finite Work and Failure Semantics

request_timeout_ms is a single overall monotonic deadline per call, including connection acquisition, resolution/connection/TLS, response headers and bounded body reading. A per-read idle timeout alone does not meet this requirement: a trickling response cannot extend the overall deadline. Transport phase timeouts cannot exceed the remaining budget. Timeout cancellation closes/releases the response; externally requested cancellation propagates without conversion into a normal failure and without retries. DNS/resolver work that cannot be stopped by the chosen transport must be documented and bounded at the caller-facing wait, without claiming an underlying worker was forcibly terminated.

Cap streamed response bytes at 262144 (256 KiB); enforce the cap even when Content-Length is absent, false or chunked. Request identity encoding and reject non-identity Content-Encoding so compression cannot bypass the cap. Parse only after a bounded complete read. The byte/version limits are proposed local guardrails, not HA upstream maxima or measured production SLOs, and require review disposition.

Finite error codes, with fixed value-free messages and a validated correlation ID:

| Condition | Code | Behavior |
| --- | --- | --- |
| HTTP 401 | auth_failed | No retry; no response-body/header echo |
| Overall/transport deadline expires | timeout | Release resources; no retry |
| DNS, connection refusal/reset or TLS verification failure | transport_failed | No underlying exception/request/URL echo |
| Any other status, including all redirects and 403/404/429/5xx | http_error | Optional integer status only; no retry/follow-up |
| Invalid/oversized/unsupported successful response | invalid_response | No partial result or raw data echo |
| Operation after explicit close | client_closed | No network request |

Classify status before successful-body parsing: a malformed or oversized 401 body remains auth_failed without reading that body. Preserve these distinct categories. A caller can explicitly make another call after a failure; a call is never replayed implicitly. Normal failures close responses and leave the client usable; explicit close is idempotent. Independent review fixes precedence for boundary races and cancellation so TC expectations are deterministic.

### Privacy and Diagnostic Boundary

Supported repr/str, public result/error exports and package-controlled logging never include credentials, request Authorization, configured endpoint, raw response/body/headers or underlying transport exception text. Reject invalid correlation IDs with a fixed diagnostic without echoing the submitted value; exclude credential/endpoint substrings from accepted IDs. A correlation ID is supplied by the caller, not obtained from an untrusted server, ambient environment or random generator.

An HTTP dependency exception can retain the credential in its request. Sanitize failures outside the active dependency-exception handler so exported errors do not retain raw exceptions via __cause__, __context__, args or custom fields; raise-from-None alone is insufficient to remove __context__. Avoid storing sensitive request/response objects on public results/errors. Verify library logging configuration and package-controlled logging with adversarial fixtures, including a server echoing the credential. User-enabled dependency wire/debug tracing, deliberate private introspection, traceback-frame local inspection and process-memory access are outside the supported diagnostic boundary and must be documented without suggesting name mangling is a security boundary.

Explicit transport internals necessarily handle the credential. HARuntimeInfo is internal adapter metadata; this increment does not expose a Home API/BFF response or certify arbitrary malicious metadata as safe for publication. Supported serialization projects only validated fields. Close behavior does not claim to erase immutable strings from memory.

## Non-goals

No change to accepted endpoint/configuration semantics without explicit review disposition.

## Acceptance Criteria

- [ ] AC1: The packaged documented client accepts the existing HAConfiguration and performs exactly one authenticated GET /api/config per runtime_info call, returning immutable typed version metadata from a fake server without retaining other configuration fields.
- [ ] AC2: Independent malformed/media/encoding/size/type/duplicate-key fixtures fail as invalid_response; all non-200 statuses classify as specified, including malformed-body 401 and refused redirects, with no partial success.
- [ ] AC3: Authentication, deadline and DNS/connection/TLS failures produce distinct fixed redacted categories; no failure is retried implicitly and an explicit subsequent request remains possible until close.
- [ ] AC4: The configured overall deadline bounds delayed headers and trickling bodies, streamed bytes stay within the cap, cancellation propagates and responses/client resources close deterministically on all paths, including repeated close and post-close requests.
- [ ] AC5: Credentials, endpoints, unrelated private HA configuration and raw dependency failures are absent from supported inspection, public errors/results and package logs; error chains and credential-echo/correlation fixtures exercise the declared boundary.
- [ ] AC6: TLS verification, redirect refusal, disabled ambient proxy/credential lookup and lack of generic/write operations are verified through counted transport/fake-server probes; normal test runs never require a private account/token or non-loopback network.
- [ ] AC7: A distinct required-HA-REST test mode rejects missing runtime/dependencies and mandatory skips with hermetic absent-component probes, while accepted configuration/provider/demo/conformance and shared-contract checks remain effective.
- [ ] AC8: Required fake-HTTP checks, lint and strict typing run on Python 3.12/3.13/3.14; direct and sdist-derived compatible wheel pairs run installed success/failure/close smoke outside checkout with -I and -O, recording source commit, interpreter, per-TC executed/failed/skipped counts and artifact hashes.

## Verification and Review Gate

Independent requirement review settles API/result/error/ID shapes, transport/dependency bounds, deadlines and cancellation, response/media limits, version grammar, status precedence, resource/serialization/diagnostic exclusions and lifecycle/test-transport ownership. TC design then independently fixes expected values and failure probes before runtime code and allocates TC IDs. No TC IDs or runtime pass claims are made at admission.

Required integration uses a controlled loopback fake HTTP server that observes the actual path, method and Authorization header. Supplement with deterministic transport/clock probes for timeout races, DNS/TLS errors and cancellation. Include a second fake destination receiving zero requests on redirects; a trickling and oversized/chunked body; raw error responses echoing sensitive markers; failures with sensitive exception chains; success with unrelated private fields; close/error recovery; ignored ambient proxy settings and no credential loading. Fictional credentials stay in test fixtures and are never included in evidence/logs.

Permit loopback network only in explicitly identified fake-server tests and installed smoke; all other network stays denied. Configuration tests retain their no-I/O guards. Preserve existing required modes and Python matrix/artifact jobs; introduce a distinct required-HA-REST mode at TC design so absent modules/dependencies or skipped mandatory cases cannot pass via ambient installations. Do not substitute an injected mock for every test of the production HTTP path.

Record tested commit, commands, platforms/interpreters, actual per-TC counts and direct/sdist SHA256 provenance. No real HA is a required environment for AC1–AC8. A live check is optional and separately attributed as executed or not executed; fake success does not establish HA/device or R1 certification.
