## Requirement Description

### Package and Public Boundary

Add an adapter-local REST module to the existing ai-family-home-device-fabric distribution. Reuse the accepted HAConfiguration, including its endpoint spelling, request_timeout_ms and explicit access_token_for_transport() boundary. Do not extend MockConfiguration, ProviderProtocol or canonical Home/State/Capability/Action envelopes for HA runtime metadata.

The public module is home_device_fabric.ha_rest, with exactly HARestClient, HARuntimeInfo and HARestError in __all__. HARestClient(configuration: HAConfiguration) exposes async runtime_info(*, correlation_id: str) -> HARuntimeInfo, async aclose() -> None and async context-manager methods. Construction/context entry issues no request; a closed client cannot be reopened. Invalid configuration type fails with fixed TypeError("invalid_configuration") before transport creation. The constructor has no public URL/header/method/transport/client injection options. TC design transcribes these choices independently rather than selecting a different API.

HARuntimeInfo exposes a read-only version: str and to_dict() returning exactly {"version": version} as a fresh mapping. Its repr/str is the constant HARuntimeInfo(<redacted>); client repr/str is the constant HARestClient(<redacted>). HARestError exposes read-only code: str, correlation_id: str | None and http_status: int | None, with to_dict() returning exactly those three fields. Its args and str contain only the fixed code; repr may include only these validated fields. http_status is present only for auth_failed/http_error, otherwise None. The absent correlation ID is reserved for invalid_correlation_id, never substituted for a valid failing call's ID. No raw request/response/cause/context fields are exported. Client/raw-credential pickle/copy/state export is refused with fixed diagnostics; public result/error inspection exports only the declared metadata. This is a supported diagnostic boundary, not resistance to deliberate private introspection.

Use httpx>=0.28.1,<0.29 as the new adapter runtime dependency, without HTTP/2, CLI, Brotli or Zstandard extras. The bounded minor series limits unreviewed API drift; transitive dependencies are not claimed locked. Implementation evidence must record actually resolved versions of HTTPX and its full dependency closure, along with compatible artifact hashes. Future range widening needs reviewed specification/verification changes. Do not change package metadata in this specification PR.

Choose HTTPX's typed async/streaming/TLS transport instead of implementing HTTP framing/cancellation in stdlib worker threads or adding another async client/native-extension packaging surface. This is a local integration tradeoff, not a claim that alternatives cannot work. Python classifiers and py.typed are insufficient compatibility evidence: AC8 must really import and exercise this transport on 3.12/3.13/3.14, including timeout and TLS-failure paths. The supported wrapper backend is asyncio on a single event loop; cross-thread/cross-loop and Trio use are outside this increment.

Each admitted runtime_info call owns a fresh private HTTPX client/transport, streamed response and cleanup; it closes them before settling. This avoids persistent cookies/session state at the cost of connection reuse, acceptable for the bounded runtime-info read. Use a private factory seam for deterministic tests only, transferring ownership to the operation, never borrowing or closing a caller-shared client. The seam must exercise production authentication/status/parsing paths, not return an already parsed result. TLS trust-store loading is transport initialization, not secret loading; configuration construction keeps its accepted no-I/O boundary.

### Authenticated Runtime Read

For each call, send exactly one GET to configured base_url + /api/config, with Authorization: Bearer followed by the explicitly supplied credential and Accept: application/json. Preserve the configuration's endpoint contract; paths, methods, headers and destinations are not caller-configurable. There are no device writes, generic request/HA-service entry points, automatic retries or reconnect scheduling.

Disable automatic redirects, ambient proxy/environment configuration, cookie persistence and implicit credential lookup. TLS certificate/hostname verification is enabled for HTTPS; there is no public verification-disable option. HTTP remains supported because accepted configuration allows it. Never forward the credential to a redirected destination, including a same-origin redirect. Response URLs, Location, cookies, server error text and headers are not public diagnostics.

HTTPX options/headers must explicitly set trust_env=False, follow_redirects=False, certificate verification enabled, transport retries=0 and Accept-Encoding: identity. No cookies are supplied or carried between operations. Redirect refusal is an intentional operational constraint: when an installation redirects HTTP to HTTPS, the caller must configure the final HTTPS endpoint directly; even an otherwise safe same-origin upgrade is http_error. Fake tests do not certify a proxy/installation's production behavior.

Status 200 is the only success status. Return only the required HA version as typed adapter-local runtime metadata; discard unrelated HA configuration, including location, coordinates, filesystem paths, unit settings and components. Accept version only when type(value) is str, 1 <= len(value) <= 128 and every character satisfies 33 <= ord(character) <= 126. This deliberately excludes all whitespace, including internal spaces, and accepts dotted development/prerelease spelling without asserting semantic-version validity or supported HA releases. Reject a projected value containing the complete supplied credential or complete normalized configured endpoint, case-sensitively, as invalid_response. Keep those defensive comparisons even when conventional HA versions cannot contain an endpoint; do not claim to detect transformed/fragmented secrets.

Positive TC examples include 2025.1.0, 2024.11.0.dev20241014 and 2023.9.0b0. Negative examples include empty/129-character strings, leading/trailing/internal spaces, NUL/control/DEL/non-ASCII characters and non-string values. Boundary examples exercise 1 and 128 characters plus whole-token/endpoint echoes. These predicates are the local adapter's accepted metadata language, not an upstream HA release grammar.

Accept a UTF-8 JSON object with a required version string. Additional fields are ignored, not retained. Reject malformed UTF-8/JSON, duplicate object keys, non-object roots, missing/wrong-type/invalid version and non-finite JSON constants. Content-Type must identify application/json, optionally with UTF-8 charset; incompatible media types/charsets fail as invalid_response. The projected result and client use the supported inspection/serialization boundaries above; no object retains the raw response as an exported diagnostic.

### Finite Work and Failure Semantics

request_timeout_ms is a single overall monotonic deadline per call, including connection acquisition, resolution/connection/TLS, response headers and bounded body reading. A per-read idle timeout alone does not meet this requirement: a trickling response cannot extend the overall deadline. Transport phase timeouts cannot exceed the remaining budget. Timeout cancellation closes/releases the response; externally requested cancellation propagates without conversion into a normal failure and without retries. DNS/resolver work that cannot be stopped by the chosen transport must be documented and bounded at the caller-facing wait, without claiming an underlying worker was forcibly terminated.

Cap streamed response bytes at 262144 (256 KiB); enforce the cap even when Content-Length is absent, false or chunked, using raw streamed bytes rather than automatically decompressed bytes. Content-Encoding must be absent or the single case-insensitive identity token; gzip/deflate/Brotli/multiple encodings intentionally produce invalid_response even if a reverse proxy normally compresses responses. Request identity encoding explicitly. Parse only after a bounded complete read. Accept the byte/version limits as local guardrails, not HA upstream maxima or measured production SLOs.

Finite error codes, with fixed value-free messages and a validated correlation ID:

| Condition | Code | Behavior |
| --- | --- | --- |
| HTTP 401 | auth_failed | No retry; no response-body/header echo |
| Overall/transport deadline expires | timeout | Release resources; no retry |
| DNS, connection refusal/reset or TLS verification failure | transport_failed | No underlying exception/request/URL echo |
| Any other status, including all redirects and 403/404/429/5xx | http_error | Optional integer status in 100–599 only; nonstandard status yields None; no retry/follow-up |
| Invalid/oversized/unsupported successful response | invalid_response | No partial result or raw data echo |
| Operation after explicit close | client_closed | No network request |
| A second operation while one is active | client_busy | No queuing or network request |
| Provided wrong-type/invalid per-call ID | invalid_correlation_id | correlation_id=None; no value echo or network request |

Classify status before successful-body parsing: a malformed or oversized 401 body remains auth_failed without reading that body. Preserve these distinct categories. A caller can explicitly make another call after a failure; a call is never replayed implicitly. Normal failures close operation-owned resources and leave the wrapper usable; explicit close is idempotent. Ordinary owned-close exceptions do not replace an already classified success/failure, and both closes are attempted; cleanup-guard/deadline expiry still produces timeout. Nonstandard HTTP statuses such as 600/999 remain http_error with http_status=None, preserving the caller ID and finite error API.

### Single Active Operation and Close Ordering

Choose one active operation per wrapper, with no queue. Validate the ID first, then check logical closing/closed state, then the busy state, and reserve the operation before the first await. Therefore an invalid ID wins over client_closed/client_busy; a valid second call fails client_busy with its own ID and zero dispatch; a valid call after close begins fails client_closed with its own ID and zero dispatch. Separate clients can operate concurrently.

aclose(), when its coroutine begins execution, marks the wrapper logically closed before its first await. It waits for an already admitted operation to finish and release its own resources, without cancelling it or extending its original deadline. That operation retains its own success/failure/timeout/cancellation outcome; close does not replace it with client_closed. Simultaneous/repeated closes share a completion event and return None, never the active call's exception. Cancellation of a close waiter propagates to that waiter without cancelling the active request or reopening the wrapper; operation cleanup still completes and a later aclose can await it. Do not await or shield the caller's whole task as the close completion mechanism. Once no operation is active, close completes without transport I/O. Re-entering a closed async context raises fixed RuntimeError("client_closed"); calling runtime_info after close instead raises HARestError("client_closed") with the call ID.

Use asyncio's monotonic deadline with an explicit expiry check before publishing a result or ordinary failure: once the observed clock is at or past the admitted operation's deadline, timeout wins over a concurrently received status/body/transport error. External cancellation propagates instead of being translated. Close/busy decisions apply only at admission; deterministic gated transport/clock tests settle race assertions, not scheduler timing guesses. Include the accepted minimum 1 ms budget in deterministic tests; loopback wall-clock assertions allow explicit scheduling tolerance and never promise exact microsecond completion.

Reserve at most 1000 ms total for operation-owned cancellation-safe cleanup after network work stops; this is a separate fixed local resource-release guard, not extra time in which a request can succeed. It cannot be restarted per resource or per close waiter. Cancelled close waiters do not cancel cleanup. Deadline or cleanup-guard expiry prevents success and produces timeout, except external cancellation still propagates. Normal production cleanup must release resources; a transport that cannot both release its owned resources and satisfy the guard fails acceptance. Neither asyncio timeouts nor this guard preempt synchronous code or forcibly terminate resolver workers; document scheduler/synchronous-finalization limits and test counted cleanup attempts without claiming hard real-time execution. Draining close uses the same completion event/budget and never starts a fresh request/cleanup budget.

### Privacy and Diagnostic Boundary

Supported repr/str, public result/error exports and package-controlled logging never include credentials, request Authorization, configured endpoint, raw response/body/headers or underlying transport exception text. Per-call correlation_id must be an exact str matching ASCII [A-Za-z0-9][A-Za-z0-9._-]{0,63}, with no coercion; reject IDs containing the complete credential or normalized endpoint, case-sensitively. Missing ID is a fixed Python signature TypeError; provided invalid IDs raise invalid_correlation_id with correlation_id=None and no submitted-value echo. A valid ID is returned unchanged on that call's HARestError, including client_busy/client_closed, not attached to the client or reused from a previous call. It is not obtained from a server, environment or random generator. Safe diagnostic IDs remain the caller's responsibility; these checks do not detect transformed credentials or arbitrary private data.

An HTTP dependency exception can retain the credential in its request. Sanitize failures outside the active dependency-exception handler so exported errors do not retain raw exceptions via __cause__, __context__, args or custom fields; raise-from-None alone is insufficient to remove __context__. Avoid storing sensitive request/response objects on public results/errors. Verify library logging configuration and package-controlled logging with adversarial fixtures, including a server echoing the credential. User-enabled dependency wire/debug tracing, deliberate private introspection, traceback-frame local inspection and process-memory access are outside the supported diagnostic boundary and must be documented without suggesting name mangling is a security boundary.

Explicit transport internals necessarily handle the credential. HARuntimeInfo is internal adapter metadata; this increment does not expose a Home API/BFF response or certify arbitrary malicious metadata as safe for publication. Supported serialization projects only validated fields. HARuntimeInfo and HARestError support pickle/copy/deepcopy round trips of their validated projections; restored errors discard traceback/cause/context/notes. Client raw-state/copy/pickle remain refused. Close behavior does not claim to erase immutable strings from memory.
