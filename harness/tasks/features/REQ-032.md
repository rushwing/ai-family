## API and identity

Add home_device_fabric.ha_mapping.HARegistryMapper(configuration),
HAMappingResult and HAMappingError. This synchronous pure API performs no I/O,
clock, randomness, environment lookup, logging or device operation.
configuration is an exact JSON object containing only schema_version:1,
home (accepted Home contract), provider_instance_id (canonical-format alias),
area_ids, device_ids and entity_ids. Each assignment object maps a nonempty,
trimmed, UTF-8 HA identifier of at most 512 characters to a canonical ID.
At most 10000 assignments per object. All assigned canonical IDs are globally
unique across Home/area/device/entity identities, even for absent resources.
Explicit assignments are the trust boundary: no slug, hash, name matching,
provider-ID-derived canonical identity or implicit persistence is permitted.
The caller owns canonical ID allocation and durable assignment retention.

map(discovery) takes the detached four-list devices/entities/areas/states JSON
export from HADiscoverySnapshot.for_mapping(). It validates the entire bounded
input before projection; no mutation, caching, partial result or fallback on
invalid data. Plain JSON values only, finite numbers, valid UTF-8, at most
32 container levels, 200000 values/keys, 16 MiB encoded JSON, 10000 records per
component. Integers are limited to 4096 bits. Repeated container aliases and cycles are rejected. Known provider
IDs are trimmed UTF-8 strings of 1–512 characters, unique per component. Devices require id, entities/states entity_id,
areas area_id and a nonempty name; states require state text and attributes
object. Nullable device_id/area_id/disabled_by references are validated; optional
name/name_by_user/original_name are nullable strings of at most 512 characters.
State strings are bounded to 4096 characters. Unknown JSON fields are ignored
semantically after validation. Missing and unknown required fields at the
four-component boundary fail; empty successful components remain valid.

## Projection rules

The canonical Home comes only from configuration. Assigned, present areas map
to area_type:other, floor_id:null, no labels/aliases; no floor/type inference.
Assigned registry devices produce one Device and one HA ProviderBinding when
at least one enabled registry entity references them. All enabled entity IDs
for that device are sorted in a single HAMapping, with device_registry_id.
A registry entity without device_id may form a standalone device only through
its explicit entity_ids assignment; its binding has null device_registry_id.
An entity_ids assignment for an entity that currently has device_id remains
reserved and participates in global canonical-ID uniqueness, but does not
split that grouped entity into a separate Device. It becomes usable only if
that entity later has no device_id; it cannot promote a missing/disabled parent.
An entity with a missing/unassigned/disabled referenced device is excluded,
never silently promoted to standalone. Device assignments and entity-only
assignments cannot share canonical IDs; provider replacement is explicit
reconfiguration using the same canonical ID for the replacement resource.

Disabled devices/entities (nonnull disabled_by) are omitted. Unassigned areas,
devices and standalone entities are omitted and counted. Unmatched state rows
never create devices; missing states do not delete enabled registry entities.
Registry devices with no eligible entities have no Device/binding and are
counted as unbound. Device area_id controls grouped devices; entity area
references do not split devices or override their location. Standalone entities
use their own area_id. Missing/unassigned area references yield area_id:null
and an unresolved-area count. unresolved_areas counts one unresolved nonnull
reference per emitted Device, including standalone Devices; it is not the
number of distinct missing areas or grouped entities. Null references and
omitted Devices do not contribute. Device names use name_by_user, then name, then
"Device"; standalone entities use name, then original_name, then "Device".
Optional blank names fall through; chosen names are trimmed. No raw identifier
is used as a display-name fallback. Canonical lists and binding members are
sorted by canonical/HA identity respectively, independent of input order.

Each call is a fresh projection, not a merge or reconciliation engine. Removed
entities disappear from bindings; if the last is removed, its Device disappears
from this result. Canonical IDs remain reserved by the caller's assignments,
so reappearance restores identity. No tombstones, deletion commands, physical
availability or epoch claims are produced. This result must not automatically
replace an existing store without a separately admitted reconciliation policy.

## Boundary and errors

Mapper configuration and results are detached immutable private JSON snapshots,
with redacted repr, forbidden copy/pickle and explicit result.for_adapter()
export returning inventory plus bindings. Validate output using accepted
Inventory and BindingCollection factories. Direct HAMappingResult construction
also eagerly validates exact JSON string inputs, bounded strict decoding,
Inventory/BindingCollection shape and references, an exact 12-member tuple of
exact integer counters in 0..10000, and matching area/device/binding cardinalities.
Invalid initial values fail before publication with finite invalid_projection
(or input_limit for bounds); no raw exception context is retained. Validated
structure/counters do not prove mapper execution or the origin of supplied data.
Ordinary summaries expose only
fixed count names and rules_version:1; no raw HA IDs, names or state attributes.
HAMappingError has finite code invalid_configuration, invalid_discovery,
input_limit, invalid_projection or internal_error, fixed str/repr/to_dict and
no retained raw exception context. Process-control exceptions propagate.
Private introspection, traceback frame locals and deliberate for_adapter()
export are outside diagnostic redaction. No public route is added.
