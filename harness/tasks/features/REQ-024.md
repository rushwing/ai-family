## Requirement description and proposed API

Add `home_device_fabric.ha_websocket` to the existing fabric distribution, with
exact exports `HAWebSocketClient` and `HAConnectionHealth`. Reuse immutable
`HAConfiguration`; a different configuration type fails immediately with fixed
`TypeError("invalid_configuration")`. Construction performs no I/O. The only
public client operations are async `run() -> None`, async `aclose() -> None`,
and synchronous `health() -> HAConnectionHealth`. No generic send/request,
subscription, credential/URL override, callback, history or device-write API.
One client owns one lifecycle on one event loop. `run` starts once, remains
pending while connected/reconnecting, and returns on terminal failure or close.
Concurrent/repeated runs reject with `RuntimeError("client_started")`; a run
after closure rejects with `RuntimeError("client_closed")`. Cross-loop async
use rejects with `RuntimeError("wrong_event_loop")` before mutation/I/O.

### Connection and protocol

Derive ws/wss from the accepted http/https root, preserve authority/port spelling,
and append `/api/websocket`. Use `websockets>=15.0.1,<16` asyncio client with no
automatic library reconnect iterator. Disable ambient proxies, redirects,
compression, extra headers, user-agent and dependency logs. WSS verifies both
certificate and hostname against system OpenSSL default roots, excluding
SSL_CERT_FILE/SSL_CERT_DIR overrides. No fallback to insecure TLS. Explicit
socket ping interval and pong timeout are 20 seconds each; close timeout is
1 second; max message is 64 KiB, receive queue 4 frames. DNS and asyncio
scheduling are not hard real-time guarantees.

One `request_timeout_ms` monotonic budget covers connect, auth_required receipt,
auth send and auth result. Server messages must be text JSON objects, unique
keys, no NaN/Infinity, type string. Binary, malformed, oversized or out-of-order
messages terminate with `protocol_error`. Require `auth_required`, send exactly
`{"type":"auth","access_token":<explicit credential>}`, then require `auth_ok`.
Ignore other fields, including version and rejected-auth messages; never retain
them. `auth_invalid` at either authentication stage or handshake HTTP 401/403
terminates `auth_failed` without retry. Connected is published only after
auth_ok. No commands are sent after authentication; any unsolicited application
message is `protocol_error` (subscriptions belong to HI-S005). WebSocket control
ping/pong/close is handled by the library. Normal and abnormal remote closes
both count as disconnection and may reconnect. Transport loss, OSError and
authentication/connect timeout are retryable; other handshake/protocol failures
are terminal. Unclassified ordinary exceptions fail closed as `internal_error`.

### Finite reconnect and health

Use REQ-022's `reconnect_delays_ms()` exactly. Initial connection is outside the
budget; at most N additional attempts occur, each preceded by its corresponding
delay. Budget is lifetime-wide and never resets on successful authentication,
so repeated short-lived successes cannot create infinite retries. Waiting uses
asyncio sleep; deterministic tests substitute a private sleep seam. Shutdown
cancels pending backoff immediately. Exhaustion publishes failed with reason
`reconnect_exhausted`, retaining the last attempt ordinal. There is no implicit
restart; construct a new client explicitly after investigating terminal failure.

`HAConnectionHealth` is an immutable frozen slots value with `state: str`,
`reason: str | None`, `reconnect_attempt: int`, `sequence: int`, and detached
`to_dict()` with exactly these keys. Initial value is disconnected/None/0/0.
States: disconnected, connecting, authenticating, connected, reconnecting,
auth_failed, failed, closed. Reasons: None, transport_failed, timeout,
protocol_error, auth_failed, reconnect_exhausted, internal_error, cancelled.
Reconnect attempt is 0 for initial connection, 1..N on retries. Sequence grows
on every published transition. `health()` is a current snapshot; no unbounded
history or externally executing callback. Health describes transport lifecycle,
not REST health, entity freshness, or physical device availability.

### Shutdown, cancellation and privacy

`aclose` permanently closes admission before its first await, cancels a worker
once, and drains its owned cleanup; simultaneous/repeated closers are idempotent.
Cancelling a close waiter propagates cancellation to that waiter while closure
continues. Shutdown during connect/auth/connected/backoff cannot reconnect or
publish connected afterward. `run` owns a separate worker: cancelling its caller
cancels/drains the worker and propagates CancelledError, publishing disconnected
with cancelled unless aclose has made closed terminal. Repeated cancellation
must not orphan cleanup. A private cleanup task shields socket.close under one
1000 ms guard and aborts the transport on expiry/close error. Process-control
BaseExceptions propagate after finally cleanup; ordinary dependency exceptions
never escape in public diagnostics. Socket operations must cooperate with
asyncio cancellation; no Python coroutine can preempt arbitrary blocking code.

Health contains only finite constants/counters, never endpoint/token/server
message/close reason/exception text. Client repr/str are constant and raw
pickle/copy/getstate export refuses. No raw diagnostic history or dependency
exception is retained. Configuration deliberately exposes transport credentials
to trusted internal code. Private introspection, traceback locals and explicitly
instrumented OS/network tracing remain outside this supported diagnostic boundary.

## Non-goals
