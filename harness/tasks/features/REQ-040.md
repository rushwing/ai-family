## Scope and placement

HI-S023 contributes to [HI-F008](../../../docs/product/home-intelligence/requirements/features/HI-F008.md).
Reuse the existing PostgreSQL audit schema, transaction-local member claims,
non-bypass application roles and MCP gateway. Add a typed home-action audit
table rather than putting unbounded request JSON into the generic Goal ledger.
Existing audit.event and Goal /audit/recent behavior remain compatible.
REQ-003/004 retain their full scope and lifecycle; this is their home-action
audit integration, not completion of the shared platform.

Persist authenticated and anonymous rejected attempts at the exact registered
home tool and its independent confirmation route. Each HTTP attempt receives
a fresh server-generated UUID and two append-only events: started before
delegation, then allowed, denied or unavailable according to the actual HTTP
status. These are boundary outcomes, never a device-success claim. A durable
started event without a terminal event means interrupted/unknown; recovery
must not infer success or automatically redispatch. Confirmation allowed means
a user proof was accepted, not physical action authorization.

The store also accepts trusted internal task/attempt correlation for later
execution integration. Retries append distinct event IDs while preserving
the same pseudonymous task/trace/idempotency references. No unique constraint
on an idempotency key may erase retry evidence or claim task deduplication.

## Privacy and record contract

Persist only version 1, random event/attempt UUIDs, database timestamp, phase
(confirmation/execution/task), finite outcome/reason, bounded duration/status,
verified family_member_id for RLS, and domain-separated HMAC-SHA256 references
for requester/home/device/capability/action/task/trace/idempotency. A private
32–128 byte audit key and bounded key ID are explicit server configuration;
rotation changes references, and deployments must retain key provenance.
Do not store JWTs, sessions, proofs, confirmation tokens, raw arguments,
provider IDs, labels, URLs, exception messages or complete payload digests.
References are equality/correlation aids, never authorization or proof of a
canonical target. Malformed/oversized individual fields become null references.
Unverified identity is anonymous, never inferred from request body or token
decoding without signature verification. Anonymous rows have null member and
are invisible to ordinary member reads.

## Database and access contract

Migration 0007 is repeatable and preserves rows. FORCE/ENABLE RLS applies.
aifam_app may INSERT only under its transaction-local member scope and SELECT
its own rows; aifam_kid may SELECT its own rows. Neither application, kid nor
oversight roles may UPDATE, DELETE or TRUNCATE. PUBLIC receives no privileges.
The existing aifam_audit_reader role has SELECT-only oversight. Production
connections must have no ownership, superuser, BYPASSRLS or DDL powers.

Authenticated reads verify the original RS256 JWT on every entry, use a fixed
projection and descending database timestamp/event order with limit 1–100.
Ordinary admin/adult/kid reads remain member-scoped. Oversight additionally
requires adult/admin, a separate explicitly configured oversight DSN, and an
exact-True trusted approval callback. An admin claim alone is insufficient.
No caller-controlled SQL role, member, filter expression or DSN is accepted.
Missing/malformed approval and database failures fail closed. The callable
read API is supplied here; a public audit HTTP API remains separate.

## Composition and failure semantics

An explicitly injected audit store enables durable home boundary middleware.
Unconfigured audit preserves the accepted guard's disabled production path;
it does not certify durable audit or authorize physical execution. Configured
audit must commit started evidence before any route/confirmation/handler
delegation. Missing key/schema/database/permissions, lock timeout or insert
failure returns fixed audit_unavailable / 503 with zero delegated calls and
no in-memory fallback. Terminal persistence failure likewise returns 503;
the committed started event remains evidence of an uncertain boundary outcome.
Unexpected route exceptions are normalized without persisting private text.
All connections/transactions release on error with finite connect/statement/
lock waits. Audit records commit independently of the business transaction,
so handler rollback cannot erase denial evidence or resurrect confirmation.

This middleware is not the future physical dispatch transaction. HI-S021
must retain REQ-039 authority/state protection through durable authorized
task/outbox intent, revalidate at dispatch, and handle terminal-audit failure
after physical effects as uncertain. No callback added here can dispatch to HA.
Accepted guard execution continues fixed 503 with zero provider/task calls.
