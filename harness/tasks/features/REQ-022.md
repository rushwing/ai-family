## Requirement Description

### Package and Public Boundary

Add a dedicated HA configuration module to the existing `ai-family-home-device-fabric` distribution. Reuse package conventions without extending the frozen mock-only MockConfiguration, normalized provider envelopes or ProviderProtocol. Configuration remains adapter-local; canonical inventory, binding, State, Capability and Action contracts stay unchanged. There is no dependency on an HA SDK or HTTP/WebSocket client for this increment.

The reviewed public construction seam accepts an explicit settings object plus a separate required token argument and returns an immutable validated configuration object. Settings cannot contain the credential field; unknown fields reject, including an embedded access_token. No implicit environment lookup, .env/file loader, CLI token flag, logging, network/DNS, clock/random input or singleton cache participates in construction. Future composition code may read private configuration and explicitly supply values. Provide a deliberate credential accessor for future trusted transport code; ordinary inspection/serialization is redacted. TC design freezes export names, signatures, public snapshots and exact error vocabulary before runtime implementation.

### Settings and Finite Limits

Settings are a strict string-keyed object; schema_version and base_url are required. Optional limits have documented defaults only when absent; explicit null, strings, floats or bool are not converted into numbers. Duration units are milliseconds. These proposed values are part of the requirement review, not hidden implementation choices.

| Setting | Type / accepted range | Default |
|---|---|---|
| schema_version | strict integer 1 | required |
| base_url | validated HTTP(S) root endpoint string, at most 2,048 characters | required |
| request_timeout_ms | strict integer 1–120,000 inclusive | 10,000 |
| reconnect_initial_delay_ms | strict integer 1–60,000 inclusive | 1,000 |
| reconnect_max_delay_ms | strict integer 1–300,000 inclusive, at least initial delay | 30,000 |
| reconnect_max_attempts | strict integer 1–32 inclusive | 8 |

Reject missing required fields, extra fields, unsupported schema versions, non-string keys and non-object settings. The separate credential must be a strict nonempty string of 1–8,192 printable ASCII characters with no whitespace/control characters. No trimming, coercion, JWT decoding or credential-authenticity inference. Missing, null, empty/whitespace-only, oversized, non-string and control/non-ASCII tokens fail construction with a fixed redacted error. Tests use obvious fictional values, never real tokens.

### Endpoint Rules

Accept absolute http/https root URLs with a nonempty syntactically valid DNS hostname or IPv4/bracketed IPv6 literal and optional port 1–65,535. Allow either no path or a single trailing slash; normalize accepted endpoint storage to a root without a trailing slash, with lowercase scheme/hostname and an explicit port preserved. Require well-formed authority/port/brackets and reject userinfo, queries/fragments (including empty delimiters), non-root paths, unsupported schemes, relative URLs, empty hosts, whitespace/control characters and malformed percent escapes. To keep URL normalization bounded, reject percent-encoded authority, non-ASCII hostnames and ambiguous backslash forms. Reviewed TC design enumerates the accepted ASCII hostname/IP grammar, default-port handling and normalized cases explicitly rather than trusting permissive URL parsing alone.

No reverse-proxy path prefix is supported in this increment; reject it instead of silently dropping it. Future REST/socket route assembly must use this reviewed root contract or introduce a separately reviewed extension. The literal scheme remains configured: no upgrade/downgrade, proxy inference, implicit TLS bypass, endpoint reachability/authentication check or host classification by DNS. Private endpoints are values supplied at runtime; public examples use reserved fictional .invalid hostnames. HTTP acceptance describes syntax only and does not dispatch a credential or make an authentication request.

### Bounded Reconnect Description

Provide a pure inspection helper that returns the exact configured reconnect delays as immutable integers for the finite attempt budget. Attempt index i is zero-based over 0..reconnect_max_attempts-1; delay(i) = min(reconnect_initial_delay_ms * 2**i, reconnect_max_delay_ms). The initial connection attempt is outside that reconnect budget. Default delays are 1,000 / 2,000 / 4,000 / 8,000 / 16,000 / 30,000 / 30,000 / 30,000 ms. No jitter, sleep, scheduler, connection health state or retry execution is implemented. Exhaustion produces a finite sequence, not an automatic reset/retry. HI-S003 will separately implement and verify lifecycle/shutdown/auth-failure policy using these settings.

### Credential Handling and Diagnostics

Configuration repr/str, ordinary redacted snapshots, object/container representations and supported public JSON serialization must never contain the token or a token-derived prefix/suffix/hash/length. Mark credential-bearing internal fields out of ordinary representation. Any supported dataclass/JSON conversion must use the documented redacted path; do not provide a public raw credential dictionary export or claim that repr exclusion alone protects generic serialization. TC review explicitly defines which serialization/introspection APIs are supported and rejects ordinary raw-secret serialization.

Ordinary snapshots identify a configured credential using a constant redacted marker, with numeric settings and a redacted endpoint marker; they omit the raw endpoint, hostname, userinfo and token. The endpoint and deliberate credential accessor remain available only through documented library access for future transport construction. This separates actual connection inputs from routine inspectable diagnostics. Input settings/snapshot mutation cannot change the validated instance; multiple instances retain separate supplied contexts.

Errors expose a fixed typed category and safe structural path made only from declared field names/fixed indexes. Unknown supplied field names become a fixed placeholder. Error code/text, exception repr, library-generated exception cause/context messages and any structured diagnostic must omit all submitted values (URL, credential and unknown keys), not just recognized token substrings. Suppress value-bearing underlying URL/parser exception messages/chains. This diagnostic boundary covers messages produced by the library, not caller-source lines or debugger/local-memory inspection; the deliberate transport accessor necessarily returns the supplied token. Freeze exact codes/paths at TC design, covering missing credential, invalid settings/URL/credential, unsupported version, bounds and invalid reconnect ordering. No parsing error falls back to defaults or produces a partially usable object.

### Documentation and Installed Use

Document a Python construction example using a fictional endpoint/token passed separately, the exact settings/defaults/bounds, redacted snapshots, reconnect index/budget semantics and transport-only credential access. Explain that validation proves accepted syntax/limits, not connectivity or authenticated HA state. Keep private deployment values out of tracked examples and evidence; do not add HA values to shared infra configuration or inspect the user's private environment/files. No new CLI or service is needed.

The module and examples run from installed compatible fabric/state-schema wheel pairs outside the checkout without pytest or repository-relative assets. Preserve paired --no-index --no-deps distribution and the existing source/installed demo/conformance behavior. Python -I smoke must use installed packages; PYTHONPATH alone is insufficient.

## Non-goals

REST/WebSocket clients, authentication requests, DNS/network access, HA runtime metadata/discovery/entity mapping, provider execution or device writes; secret-file/environment loaders, credential rotation/store/keychain, CLI token input or secret scanning of private files; live TLS/proxy/redirect handling or reverse-proxy path prefixes; connection health/scheduling/sleep/retries/shutdown; production authorization/audit/queues, State persistence, UI/R2 workflows; changing existing mock/provider/shared contracts, HI-F001/HI-F009/R1 completion or live certification.

## Acceptance Criteria

- [ ] AC1: A dedicated packaged HA configuration API constructs immutable isolated instances from explicit settings and a separate credential, rejects unknown/invalid/missing fields without coercion and preserves all existing mock/provider/shared exports and behavior.
- [ ] AC2: Endpoint validation and normalization follow the reviewed HTTP(S) root/authority/port/ASCII grammar, reject userinfo/query/fragment/path and malformed forms with fixed value-free diagnostics, and perform no DNS/network/environment lookup.
- [ ] AC3: Missing/null/blank/non-string/oversized/control/non-ASCII credentials fail closed; accepted tokens are absent from supported ordinary representations/snapshots/serialization and diagnostics, with raw credential access limited to the documented deliberate transport accessor.
- [ ] AC4: Exact millisecond defaults, strict integer inclusive limits and initial<=max ordering hold; zero/negative/bool/fraction/string/null/non-finite/out-of-range inputs reject without fallback, while boundary values remain accepted.
- [ ] AC5: Pure reconnect inspection returns the exact finite capped doubling schedule for the declared budget, including default and min/max/cap cases, without time/random/sleep/scheduler effects or implicit budget reset.
- [ ] AC6: Immutable/detached context and redacted endpoint/token snapshots remain stable under input/export mutation; typed errors and library-generated exception chain messages expose only fixed codes/structural paths, including adversarial unknown keys and parser failures.
- [ ] AC7: Required offline acceptance executes independent positive/negative/boundary/redaction cases, rejects absent runtime or any required skip, and guards against unintended I/O/network/clock/random/environment access while retaining all existing shared/provider/demo/conformance checks.
- [ ] AC8: Python 3.12/3.13/3.14 CI executes required configuration checks, lint and strict typing; direct-built and sdist-derived compatible wheel pairs exercise successful/rejected construction, redaction and reconnect inspection with python -I outside checkout and -O, recording tested commit/interpreter, per-TC counts and artifact hashes.
