## API and scope

Add `home_device_fabric.home_queries.HomeQueryService`, `QueryResult` and
`HomeQueryError`. Construct with keyword-only `store` (an exact accepted
CurrentStateStore) and `capabilities` (a canonical JSON list of records with
exact keys home_id, device_id, capabilities). Each record contains only
validated canonical CapabilityDescriptor dictionaries, with unique ID/version
pairs, sorted by that pair. Duplicate home/device records are rejected.
Configuration is a detached immutable metadata snapshot. Unknown home/device
records are inert and never establish inventory membership or permissions;
membership always comes from the store. Empty configured capabilities means
known empty; no record for a known device returns uninitialized, not empty.
The trusted adapter extracts descriptors from inference output; raw provider
mappings are rejected by descriptor validation, never exposed to callers.

Typed methods `home`, `areas`, `devices`, `device`, `states`, `state`, and
`capabilities` accept a trusted RequesterContext dictionary and explicit
home_id. `devices` optionally filters by area_id; a nonexistent area returns
not_found and a known empty area returns a found empty list. Resource selectors
are canonical IDs. `state`/`states` require explicit integer now_ms/max_age_ms;
there is no ambient clock. Output ordering is canonical ID order.

Every method first calls the store's authorization, before selector validation,
lookup or metadata access. Exact subject/member/home/role grants are reused;
read and write grants permit queries, kid read grants remain scoped. A caller
context is a trusted composition input, not an authentication credential.
Authentication and construction/revocation of a service/store remain the
composition owner's responsibility. Forbidden callers cannot distinguish
missing resources or malformed selectors. No new role-based permission policy.

Add authorized `CurrentStateStore.inventory(context, *, home_id)` returning
the accepted immutable Inventory, and `snapshot(context, *, home_id, now_ms,
max_age_ms)` returning all StateViews as an immutable tuple captured under
one store lock. Queries never mutate state, grant access, contact a provider,
rebuild inventory or publish observations. Individual calls are consistent;
separate calls do not claim a multi-call transaction. Inventory is fixed for
the store lifetime and metadata for the service lifetime.

## Results and errors

QueryResult has immutable status (`found`, `not_found`, `uninitialized`) and
detached `to_dict()` JSON `{status, data}`. Public construction validates the entire result envelope
using the same bounded plain-JSON rules as configuration; unsupported types,
nonfinite values, aliases/cycles and limit violations raise redacted
HomeQueryError(invalid_configuration) without a retained cause/context.
Process-control exceptions propagate. Invalid status retains ValueError.
Missing canonical device/area returns
not_found with null data. Known state without observations remains found with
the store's uninitialized freshness, unknown availability and empty reports.
State queries preserve desired/reported separation, revision, observation times,
availability and freshness exactly. now-updated == max_age remains fresh;
greater age is stale; clock regression is an explicit error. Capability
metadata implies neither availability nor state freshness nor authorization
to execute described actions. Home returns the canonical Home record, areas
the canonical Area list, devices canonical Device records, states StateView
records, and capabilities canonical descriptors without provider bindings.

Finite public HomeQueryError codes: invalid_configuration, invalid_context,
forbidden, invalid_selector, invalid_time, clock_regression. No submitted
values or retained exception cause/context on supported errors. Ordinary
service/result repr is constant, with no raw metadata. Service/result refuse
pickle and copy/deepcopy via serialization hooks. Private introspection and
traceback locals are outside supported diagnostics. Process-control exceptions
propagate. Configuration uses the accepted bounded plain-JSON validator
(32 levels, 200000 nodes/keys, 16 MiB, finite numbers, valid UTF-8,
4096-bit integers, no aliases/cycles) before descriptor validation.
