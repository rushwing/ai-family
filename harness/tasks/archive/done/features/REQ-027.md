## API and protocol

HAStateSubscriptionClient(configuration, callback, *, delivery_timeout_ms=1000)
accepts exactly HAConfiguration, a callable async consumer and an exact int
timeout in 1..60000. Construction performs no I/O. Public operations are async
run/aclose, transport health(), and subscription_health(). Single-use/same-loop
admission and cleanup follow REQ-024. Invalid constructor inputs fail before I/O.

After authentication send exactly {id:1,type:subscribe_events,
event_type:state_changed} once per socket. Within request_timeout_ms await a
result with exact integer id 1 and exact boolean success. A rejection terminates
with subscription_rejected; missing/malformed/mismatched acknowledgement never
establishes readiness. A successful result must carry result:null.

Only subsequent event frames with exact integer id 1 and an event object whose
event_type is state_changed are delivered. Require a data object, a nonempty
string entity_id, and present old_state/new_state values each object or null.
Transport envelope validation does not normalize or interpret state contents.
Duplicate JSON keys, nonfinite numbers, binary/oversized/deeply malformed JSON,
wrong IDs/types and unsolicited results terminate with protocol_error. The
existing 64 KiB message and four-frame transport queue limits remain in force;
accepted event/result structures have at most 32 nested levels.

The callback receives the newly decoded event object (without the wire wrapper),
in receive order, one at a time. It must return an awaitable completing within
delivery_timeout_ms. Failure/invalid return terminates with delivery_failed;
timeout terminates with delivery_timeout. No automatic callback retry, event
history or application queue; reads pause during delivery, applying backpressure.
The consumer is trusted adapter code: it must cooperate with cancellation and
must not block the loop. Awaiting aclose inside delivery rejects with
close_from_consumer to prevent joining its own reader task. The supported
consumer shutdown pattern signals a supervisor task started outside delivery,
then returns; the supervisor awaits close. Do not await shutdown indirectly
through a child task, gather or wait_for: the direct task-identity guard cannot
reject every indirect dependency, and closing cancels in-flight delivery (which
can cancel a child close waiter). This is not a graceful consumer-completion
protocol; all consumers must cooperate with cancellation. Its event payload is
private provider data, not a public
diagnostic; the client never logs or retains payloads in health. Cancellation
cannot undo consumer effects. No exactly-once, gap-free or replay guarantee is
made across reconnect; later reconciliation is HI-S007.

## Health, recovery and shutdown

HASubscriptionHealth has state (idle, subscribing, subscribed, disconnected,
reconnecting, rejected, failed, closed), reason (None or finite transport and
subscription/delivery categories), sequence (nonnegative exact int), and a
subscribed boolean property. Snapshots and detached to_dict projections contain
no payload, endpoint, credential or peer error text. Sequence changes only when
state/reason changes. Transport connected alone never means subscribed.

Every new authenticated socket requires its own successful acknowledgement.
Transport loss clears readiness before reconnect. Transient loss/ack timeout use
the original lifetime budget; protocol/rejection/delivery errors are terminal.
Close freezes closed subscription health before waiting, cancels delivery/receive
and drains socket cleanup. Socket closure/abort removes that connection's server
subscription; no extra unacknowledged unsubscribe command is required. No callback
starts after close; late completion cannot reopen readiness. Repeated/concurrent
close and cancelled close waiters retain the existing owned-drain behavior.
Public repr, serialization refusal and finite diagnostics follow REQ-024.
