## 背景

知微 Home Intelligence 前端原型此前位于独立本地仓库，产品讨论、原型和 `ai-family` 平台架构之间缺少一个可版本化、可审阅、可供 Agent 渐进读取的交接边界。

`human-001` 决定采用 modular monorepo：前后端保持独立部署单元，但产品定义、契约、Harness 和实现位于同一个仓库。GitHub Project 负责目标、日期、Release 和组合进度；Harness 继续作为正式工程状态机和门禁的单一权威。

## 需求描述

1. 把当前已跟踪的 Web 原型源码迁入 `apps/home-intelligence-web/`，不包含依赖、构建缓存和密钥。
2. 在 `docs/product/home-intelligence/` 建立 PRD、Handover、架构、Roadmap 和项目管理入口。
3. 将需求工作簿保存为产品需求基线，并提供同版本的 `roadmap.yaml` 层级索引。
4. 用声明式配置记录 GitHub Project 字段、视图、Milestone 和 Harness 状态映射。
5. 明确 `Harness → GitHub` 单向同步；GitHub Project 不得反向推进生命周期。
6. 本 PR 合并前不创建外部 Project、Issue 或 Milestone，避免未评审状态写入第二套系统。

## 非目标

- 不接入真实家庭设备或厂商凭证；
- 不实现家庭中枢 API、MCP Server、队列消费者或 Ontology；
- 不在本 REQ 批量创建 68 个正式 Harness REQ；
- 不新增 `HomeAgent`；
- 不在 PR 合并前物化 GitHub Project。

## 验收标准明细

- `apps/home-intelligence-web/` 可执行 `npm ci`、`npm run lint` 和 `npm run build`；
- 产品目录的 README 能在 L0→L3 路径中找到全部交付件；
- Excel 包含 6 个 Roadmap、18 个 Epic、68 个 Story 和 12 个示例 Task；
- `roadmap.yaml` 的 Roadmap/Epic/Story 数量与 Excel 一致，所有 Story ID 唯一；
- GitHub Project 配置包含字段、六个视图、P0–P4 Milestone 和完整 Harness 状态映射；
- GitHub/Harness 权威字段和同步方向无歧义；
- `python tools/check_layout.py`、`python tools/check_agents.py` 和相关治理门禁通过；
- 仓库不包含 `.env`、密钥、`node_modules`、`.next`、`dist` 或本地运行状态。
