## API and authorization

Extend CurrentStateStore with advance_epoch(context, *, home_id, epoch) and
apply(context, *, home_id, device_id, event, now_ms). Every operation uses the
existing exact trusted-context write grant before metadata validation, lookup
or payload inspection. Read-only/kid/no-grant/cross-home callers cannot mutate
events or fences. The caller supplies context from authenticated identity;
this library does not authenticate or expose a route.

advance_epoch explicitly pins one exact nonnegative integer generation per home,
under the same process lock as apply/put/rebuild. No automatic epoch allocation.
Initially unpinned; apply requires a pin. Equal re-pin is idempotent. Decreasing
the pin or pinning below any stored report/availability/intent-baseline epoch
fails epoch_regression at (epoch,) without change. Higher generations retain
snapshots, intent, revisions and freshness; they fence old callbacks for every
device in that home. Return the pinned integer. Other homes remain independent.
The owner must coordinate one ordering domain per home, including provider
instances, and allocate a new generation when sequence numbering resets.
Persistent epochs and snapshot/live-event reconciliation remain HI-S007 work.

apply accepts canonical DeviceState JSON, such as normalizer.normalize(...).
to_dict(), as an observation delta. It rejects non-None desired_state with
unexpected_intent at (event,); intent can only be managed through existing owner
snapshot replacement. All provided reports and availability require ordering
and must belong to the pinned epoch; wrong generations fail epoch_mismatch at
(event,) even if stale. A sparse report map is legal, including empty for offline
events. Identity must exactly match the requested home/device. No creation.
Valid unknown device returns StateNotFound before payload inspection.

## Atomic merge, replay and errors

After authorization, validate device ID and exact nonnegative now_ms, then under
the store lock perform lookup, clock-regression check, pin check, full event
parse, identity/intent/order validation, and shared apply_state_update. Invalid
canonical shape, missing ordering or conflicting same-order replay is invalid_event
at (event,), suppressing underlying canonical error messages/context in formatted
tracebacks. Unknown pin is epoch_uninitialized at (epoch,). Error precedence is
the stated order; rejected operations leave all rows, revisions, times and pins
unchanged. A stored future generation introduced by trusted put/rebuild must be
accommodated by advance_epoch before application (otherwise invalid_event).

Reuse accepted canonical per-member ordering: newer reports/availability replace
their corresponding members; older members are ignored independently; exact
typed same-order replay is a no-op and conflicting replay rejects the whole delta.
A late event may fill a previously unseen report without regressing newer
availability. Mixed fresh/stale members merge independently, with one publication.
Keep desired_state and omitted reports unchanged. Offline/recovery events change
availability without clearing retained reports; unknown observations remain
explicit unknowns, never coerced to false/zero. Timestamps are source observations,
not an ordering authority. Callers must keep ACKs separate from observations.
Canonical DeviceState has no delta/origin marker: schema-valid full snapshots
and normalized deltas are indistinguishable and use the same merge semantics.
Raw ACK envelopes fail canonical validation; this API cannot prove the origin
of an ACK that a caller has incorrectly converted into canonical observations.
An enforced origin marker would require a future shared-contract change.

Publish only when at least one canonical member changes, incrementing device
revision once and setting updated_at_ms to now_ms. No-op replay/stale input returns
the existing immutable StateView, evaluating freshness with max_age_ms=0; it does
not refresh ingestion time or bump revisions. A newer ordering with equal value
is a real observation and increments once. The entire operation shares the
existing lock with snapshot replacement/rebuild and epoch advancement; returned
views and inputs remain detached. Existing read/put/rebuild behavior is preserved.
