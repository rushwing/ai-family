## API and boundary

Implement pure offline home_device_fabric.ha_normalization. HAEventNormalizer(
*, inventory, bindings, provider_instance_id, profiles) validates detached JSON
inventory and BindingCollection references before use. Profiles are a list of
exact {entity_id, kind} objects; kind is switch, curtain or temperature. Every
profile must name a bound HA entity in the selected instance, with no duplicates.
A selected binding must have exactly one entity: multi-entity device availability
aggregation is deferred and rejects configuration, rather than guessing online.
Every HA binding in that instance must have exactly one profile; other instances
and mock bindings remain separate. Empty selected collections/profiles are valid.
Entity names never determine canonical identity, kind or capabilities. Profiles
are explicit adapter configuration, not discovery or capability registration.

normalize(event, *, ordering) accepts the decoded event object delivered by
REQ-027, not its wire wrapper. Validate event_type state_changed, data object,
nonempty trimmed entity_id, present old_state/new_state objects or null, and
new_state.entity_id equal to data.entity_id. Old state is not an observation.
Require event.time_fired as an explicit ISO timestamp with Z or numeric offset,
0–6 fractional digits and valid calendar/clock; normalize to UTC Z. Numeric
offsets range from -23:59 through +23:59 inclusive; these are durations,
not a civil-time-zone whitelist (offsets beyond ±14:00 are accepted). Never read a
clock or derive ordering from timestamps. Ordering.from_dict requires exact
nonnegative epoch/sequence integers supplied by the adapter owner. This pure
helper allocates no epoch, sequence or duplicate cache. Same event/order yields
identical output; canonical apply_state_update handles stale/replay/conflict.
Callers must retain the same ordering for a replay and establish epochs outside
this helper; no source deduplication or reconnect reconciliation is claimed.

Return a validated DeviceState delta (desired_state None, canonical identity,
reported_state and availability). No provider IDs, attributes, old state, context
or complete HA payload escape into its JSON projection. The delta is applied
with apply_state_update(reported_state=..., availability=...), never by replacing
a stored DeviceState wholesale. It neither clears desired intent nor submits ACK
or action evidence. Detached frozen records retain no input dictionaries.

## Conversion semantics

- switch: exact HA state on/off becomes known is_on true/false.
- curtain: open/closed/opening/closing plus exact integer current_position in
  attributes, 0..100, becomes known position_percent; no inferred endpoints,
  rounding or bool coercion. Missing position yields explicit unknown.
- temperature: decimal finite HA state string at least -273.15 with unit_of_measurement exactly
  °C becomes known temperature_c; no unit inference/conversion or bool coercion.
- Every non-null new_state requires attributes to be a JSON object, including
  unknown/unavailable states; missing/null/non-object attributes fail with
  malformed_object at event.data.new_state.attributes. Removal (new_state null)
  has no attributes requirement.
- state unknown yields an explicit unknown mapped property and unknown
  availability. unavailable or new_state null yields offline availability with
  no property update, retaining historical values when applied. Neither becomes
  false/zero/online. Otherwise successfully converted states are online.
- Wrong state types, unrecognized states, malformed attributes, invalid numbers,
  unsupported units, unknown entity/instance or mismatched identity produce
  HANormalizationError with finite code and fixed tuple path, without submitted
  values or arbitrary keys. Configuration errors redact underlying validation
  diagnostics. Canonical DeviceState rejection becomes invalid_observation at
  the fixed path ("observation",), suppressing underlying diagnostic text.
  No fallback binding, inferred state or partial success.
