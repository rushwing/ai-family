## Observed failures

In the reviewed Windows CPython 3.13.2 environment, the full required fabric
suite has three pre-existing REST test failures and the required shared suite
has one pre-existing inventory failure. The user-supplied second/third reviews
report the same failures on base f2e201b and PR #51 heads. The third reports
694 fabric passes plus three failures (697 total); the prior shared run reports
1794 passes plus one failure. Targeted WebSocket/gate tests and Linux CI pass.

1. test_real_overall_deadline_headers_and_trickle, both parametrizations, assumes
   one server-observed request within an 80 ms total budget, including transport
   setup. A legitimate Windows setup/scheduling timeout can precede receipt.
2. test_failed_connection_has_exactly_one_tcp_attempt instruments
   socket.socket.connect and expects the sole observed address to equal the
   bound-but-open target socket's port. The Windows record differs by 1–2 ports.
   Windows Proactor self-pipe/socketpair setup can also call that method, while
   native asynchronous connection paths can bypass it. Treat the recorded
   mismatch as a test-instrumentation issue to investigate, not proof that the
   production transport changed the target port.
3. test_cli_actionable_repeatable_failures[unreadable-None] directly calls
   os.geteuid, which is unavailable on Windows.

## Expected behavior and proposed repair

Make required acceptance test fixtures portable without weakening deadlines,
zero-retry semantics or permission-error validation and without hiding cases
behind unconditional Windows skips. Distinguish event-loop infrastructure from
the client attempt, measure the intended connection abstraction on both event
loops, and use controlled clock/transport fixtures where timing is the subject
of the assertion. Use an explicit platform-aware unreadable-file fixture or
controlled permission failure; account for administrator/root behavior.
Confirm the precise instrumentation/setup cause when implementing the fix.
