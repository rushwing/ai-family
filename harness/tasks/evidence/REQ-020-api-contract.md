# REQ-020 Demo API and TC Design Contract

Frozen combined-delivery API accepted under [human final authorization](../archive/done/features/REQ-020.md); PR #40 merge and done archival are recorded in [closeout evidence](REQ-020-review-acceptance.md). No REQ-019 provider API or capability revision changes. TC frontmatter owner identifies the actual text designer (generator-001 under the explicit combined-delivery exception); code author is attributed separately, also generator-001. No independent reviewer authorship is asserted. Historical req_impl stopping and future-review scheduling were superseded by the human final review/merge disposition; actual TC text/code attribution is preserved.

Public exports from `home_device_fabric.scenarios`: `MockSwitch`, `MockCurtain`, `MockTemperatureSensor` (immutable model metadata), each with build(scenario) and validated registration(); `configuration()` returns a fresh three-device validated configuration; `build_scenario(device: str, scenario: str) -> tuple[DemoCase, ...]`; `DemoCase` contains explicit initial inputs, independently scripted future deliveries, optional request, expected task/rejection, and virtual horizon. From `home_device_fabric.caller`: `execute_case(case: DemoCase, *, configuration_data: object = None, advance_to_ms: int | None = None) -> dict`; `run_demo(device: str, scenario: str) -> dict`; `canonical_json(value: object) -> str`; `DemoError` with fixed value-free code. CLI `python -m home_device_fabric.demo --device NAME --scenario NAME`.

Device/scenario matrix: switch success (on/off), timeout, offline (unknown/known), mismatch, stale, wrong-epoch, deadline-tie, late, malformed; curtain success (0/100/40), timeout, offline (unknown/known), mismatch, stale, wrong-epoch, deadline-tie, late, invalid-position (-1/101/1.5/true); temperature observe (0/-5.5/21.25 Celsius), offline (unknown/known), write-rejected. IDs: home-demo, mock-demo, device-switch/device-curtain/device-temperature; revision 1 only. Fixed fictional timestamp 2026-01-01T00:00:00Z is fixture provenance, not wall time.

Each case owns a fresh MockProvider. All three devices are discovered, with exact separate bindings/support and descriptor metadata. Output descriptors match the canonical exact (capability_id, capability_version) pair, including empty events, even if other revisions coexist. Before dispatch, fixture inputs are admitted through NormalizedInput and applied by shared State helpers. These caller-fed initial inputs and sensor observations have no fabricated provider attempt or Task; provider scheduling is used for every dispatched action delivery. The provider snapshot starts unknown; caller State is the authoritative demonstration projection.

JSON top-level fields exactly: schema_version=1, simulation=true, device, scenario, discovery, capabilities, units, cases, dispatch_count, verified. capabilities contains unchanged validated descriptors. units is caller metadata keyed by exact revision-1 identity: temperature_c=degrees_celsius, position_percent=percent, otherwise empty; no schema field is added to capability descriptors. Each case: name, initial_state, ready_state, final_state, timeline, task, result, rejection, dispatches, dispatch_count. Absent task/result/rejection are null. Each timeline entry: time_ms, kind, record, state, task_state, error. Kinds: state_input, dispatch, provider_outcome. record is the validated input, dispatch log or provider outcome; state is caller State after processing; task_state is nullable; error is nullable fixed {code, source}. Caller timeline is not a REQ-016 event and does not enter the provider event channel.

Rejection codes/sources: invalid_request/action, offline/caller. State errors recorded as rejected_state/state; ineligible convergence as ineligible_evidence/action. Unsupported selections raise DemoError(unsupported_scenario); scenario mismatch raises DemoError(expectation_failed). CLI exit 0 means expectations verified (including expected negative outcomes); exit 1 internal/expectation failure; exit 2 unsupported arguments or combination. Diagnostics are fixed and never echo argument values, paths or exception messages. CLI help exits 0. Runtime expectation checks use explicit exceptions and remain effective under -O.

Canonical JSON: json.dumps(value, sort_keys=True, separators=(",", ":"), allow_nan=False), stdout followed by one newline. Compare full stdout text across fresh invocations; lists preserve chronological/case order, booleans remain distinct from numbers. No ambient IDs/timestamps/configuration. All reports are fixture literals supplied independently of action arguments.

TC groups: 01 discovery/packaged models; 02 switch/curtain completion and mismatch; 03 read-only temperature/unknown/offline and invalid arguments; 04 deadlines/ACK/stale/epochs/late/repeat delivery/large jumps; 05 CLI exact text/optimized behavior/errors/independent oracle; 06 mutation isolation/ambient denial/missing-runtime gate/direct and sdist wheel pairs. Acceptance flag --require-demo-runtime fails absent code or required skips and preserves --require-provider-runtime plus six shared flags.

The temperature model's write_temperature is deliberately nonexistent and only exercises real read-only request rejection. The action provider is reconstructed once its complete attempt script is known (REQ-019 freezes it at construction); caller State remains the authoritative projection, while the new provider snapshots start unknown. CLI catches internal exceptions for fixed diagnostics; library run_demo/execute_case propagate exceptions for debugging. Gate acceptance probes use local import stubs and explicitly reject fallback to real installed modules. Optional missing-runtime collection exempts only test_gate.py, allowing gate self-tests before implementation; required flags still reject absent runtime and every skip.
