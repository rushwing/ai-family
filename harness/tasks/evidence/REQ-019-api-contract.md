# REQ-019 — Frozen TC API contract

TC design by evaluator-001 under human proceed disposition; external approval pending.

Shared imports: `state_schema.provider_contracts.ProviderError`, `MockConfiguration`, `DeviceRegistration`, `NormalizedInput`, `ProviderOutcome`. Immutable records expose `from_dict`/`to_dict`; nested JSON snapshots are detached. `ProviderError.code` is one of `invalid_json`, `invalid_configuration`, `invalid_input`, `invalid_outcome`, `invalid_task`, `binding_mismatch`, `unsupported`, `invalid_attempt`, `invalid_time`, `invalid_settlement`, `advance_in_progress`; `.path` is a tuple of safe fixed field names/indexes and `.message` equals a fixed reason. No supplied identifiers/values or exception chains appear.

Configuration is exactly the eight REQ-019 fields. Scenario fields are exactly `task_id`, `attempt_id`, `deliveries`; each delivery is exactly `delay_ms`, `input`, `outcome` with precisely one non-null. Task/attempt identifiers use REQ-018 token grammar. Scenarios are unique by task/attempt, including empty scripts. Delays are nonnegative strict integers. Outcomes are full existing ActionResult envelopes wrapped with `schema_version`, `provider`, `provider_instance_id`, `result`; only scripted ACK (`running` or `acknowledged`) or `failed` is permitted. All outcomes revalidate contextual action output/correlation/policy on submission. Timeout is generated by the simulator. Success comes from explicit caller State/event integration, never synthesized observations.

Normalized inputs have exactly `schema_version`, `provider`, `provider_instance_id`, `home_id`, `device_id`, `kind`, `capability_id`, `capability_version`, `member`, `payload`, `correlation`. Provider is `mock`; kinds are `property`, `availability`, `event`. Property payload is existing Observation; availability payload is existing Availability, with null capability/version/member; event payload has exactly `value`, `ordering`. Correlation is null or exactly `task_id`, `trace_id`. Validate capability support and member/payload at configuration admission. Correlated scenario items must match the submitted task/trace, device and capability. Uncorrelated inputs remain independent and survive cancellation.

Fabric imports: `home_device_fabric.ProviderProtocol`, `MockProvider`, `Delivery`. Runtime-checkable protocol: `discover() -> tuple[DeviceRegistration, ...]`, `snapshot() -> tuple[DeviceState, ...]`, `submit(task: object, *, binding: object, attempt_id: object) -> None`, `advance(now_ms: object) -> Iterator[Delivery]`, `settle(task: object) -> None`; `now_ms`, `dispatch_log`, `delivery_log` properties. Discovery registrations expose separate `.binding` plus supported pairs. Internal initial snapshots have no desired intent, no reports and unknown availability. Consumed normalized property/availability inputs update only private detached snapshots through State helpers with each active Task's frozen epoch, default epoch 1 for independent inputs. Wrong/stale updates are consumed but do not overwrite accepted data. Caller owns shared State and Task, applies actual helpers between yields, then calls `settle` for a terminal task. Settlement must match original frozen request/requester/dispatch context and pass real validate_task. It suppresses subsequent action outcomes/deadlines; cancellation also suppresses correlated action inputs, while independent inputs survive. It never erases consumed observations.

`Delivery` is immutable with `time_ms`, `input: NormalizedInput | None`, `outcome: ProviderOutcome | None`; `.to_dict()` returns detached records. `advance` processes all deadlines/deliveries through target inclusive; same-time deadlines precede insertion-ordered deliveries. Yield before next processing step, allowing settlement after each item. Exhaust iterator to finish the clock; closing early leaves it at the last consumed processing time and retains remaining work. Nested advancement/submission during iteration rejects; settlement is permitted. Snapshots never create freshness. Explicit attempts are unique per task/attempt, require an admitted script, and cannot resubmit an active/terminal task ID. Retry uses caller-created task ID and explicit script; provider does no replay classification or automatic retry.

Packaging: `ai-family-home-device-fabric` version 0.1.0 depends on `ai-family-state-schema>=0.1.0,<0.2`; `src/home_device_fabric`, py.typed, pytest required-runtime gate.
