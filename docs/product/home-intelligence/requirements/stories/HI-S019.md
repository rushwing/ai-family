# HI-S019 — Define Action Request, Result and Task contracts

## Context

This R1 backend slice contributes to [HI-F007](../features/HI-F007.md). Existing legacy story references express related scope; they do not prove runtime delivery. See [CROSSWALK](../../CROSSWALK.md).

## Outcome

Define Action Request, Result and Task contracts. After merge this contract, service or verification increment is available independently; later callers may integrate it without enabling unfinished device writes.

## Scope

- Requests contain canonical device/capability/action, typed arguments, trusted requester context and idempotency key.
- Task/result contracts distinguish accepted, running and terminal outcomes with task_id and trace_id.
- Completion policy separates transport ACK from event-confirmed or state-converged success.

## Non-goals

Other stories in the parent feature; R2 workflow behavior; new UI screens; arbitrary vendor actions; weakened authorization or confirmation.
