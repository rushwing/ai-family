# HI-S022 — Provide shared action guard entry point

## Context

This R1 backend slice contributes to [HI-F008](../features/HI-F008.md). Existing legacy story references express related scope; they do not prove runtime delivery. See [CROSSWALK](../../CROSSWALK.md).

## Outcome

Provide shared action guard entry point. After merge this contract, service or verification increment is available independently; later callers may integrate it without enabling unfinished device writes.

## Scope

- Trusted JWT identity and member/device policy are checked before action dispatch.
- Writes require the ADR-010 user confirmation boundary; ordinary Agent bearer requests cannot self-confirm.
- Offline, unauthorized and unsupported actions fail closed with zero provider calls; existing kid restrictions remain in effect.
- Before enabling physical writes, confirmation issuance and consumption are durable, atomic and replay-safe across restart and multiple instances. Reuse the verified shared gateway persistence implementation; if unavailable, this Story remains blocked rather than duplicating or bypassing it.

## Non-goals

Other stories in the parent feature; R2 workflow behavior; new UI screens; arbitrary vendor actions; weakened authorization or confirmation.
