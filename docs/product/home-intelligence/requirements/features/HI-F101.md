# HI-F101 — Workflow Runtime

## Outcome

A bounded workflow executes typed Trigger, Condition, Action, Wait, Timeout and Retry steps.

## User / System Value

A bounded workflow executes typed Trigger, Condition, Action, Wait, Timeout and Retry steps. This capability is independently demonstrable through the scenario below.

## Scope

- A versioned workflow definition accepts only registered typed steps and canonical device/capability references.
- Waits and retries are bounded; failures identify their step and chosen stop/continue behavior.
- Actions retain task, policy and audit semantics.

## Non-goals

AI plan generation; creating R2 stories now.

## Architecture Boundaries

Inherit [architecture alignment](../../ARCHITECTURE_ALIGNMENT.md), ADR-016 and ADR-010. Provider identifiers stay in adapters and ProviderBinding; device writes remain governed asynchronous tasks.

## Acceptance Criteria

- [ ] A versioned workflow definition accepts only registered typed steps and canonical device/capability references.
- [ ] Waits and retries are bounded; failures identify their step and chosen stop/continue behavior.
- [ ] Actions retain task, policy and audit semantics.
