# HI-F004 — Capability Model

## Outcome

The same typed capability contract can be implemented by different providers.

## User / System Value

The same typed capability contract can be implemented by different providers. This capability is independently demonstrable through the scenario below.

## Scope

- Versioned capability contracts include parameter/result schemas, risk, timeout, idempotency and completion policy.
- Switchable, Positionable, TemperatureSensor, HumiditySensor, PowerMeter and BatteryPowered have testable schemas and explicit units/ranges.
- Cleanable, Navigable, Feedable, Speakable and PresenceSensor are named extension points without premature runtime implementations.

## Non-goals

Brand-specific capability semantics; a full RDF inference runtime.

## Architecture Boundaries

Inherit [architecture alignment](../../ARCHITECTURE_ALIGNMENT.md), ADR-016 and ADR-010. Provider identifiers stay in adapters and ProviderBinding; device writes remain governed asynchronous tasks.

## Acceptance Criteria

- [ ] Versioned capability contracts include parameter/result schemas, risk, timeout, idempotency and completion policy.
- [ ] Switchable, Positionable, TemperatureSensor, HumiditySensor, PowerMeter and BatteryPowered have testable schemas and explicit units/ranges.
- [ ] Cleanable, Navigable, Feedable, Speakable and PresenceSensor are named extension points without premature runtime implementations.
