# HI-F008 — Action Guard & Audit

## Outcome

All physical actions are authorized, confirmed where required and auditable.

## User / System Value

All physical actions are authorized, confirmed where required and auditable. This capability is independently demonstrable through the scenario below.

## Scope

- Every entry point uses a common guard with trusted identity, member/device policy, capability validation and fail-closed behavior.
- Write confirmation follows ADR-010; the agent cannot issue its own confirmation proof.
- Durable append-only audit records cover requester, task/trace, device, capability, action, redacted arguments, result, duration and error.

## Non-goals

Advanced autonomous policies; weakening existing write confirmation or child restrictions.

## Architecture Boundaries

Inherit [architecture alignment](../../ARCHITECTURE_ALIGNMENT.md), ADR-016 and ADR-010. Provider identifiers stay in adapters and ProviderBinding; device writes remain governed asynchronous tasks.
