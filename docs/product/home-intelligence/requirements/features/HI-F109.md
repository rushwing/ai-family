# HI-F109 — Workflow Timeline / Audit

## Outcome

Members can explain a workflow run through its authorized timeline and action evidence.

## User / System Value

Members can explain a workflow run through its authorized timeline and action evidence. This capability is independently demonstrable through the scenario below.

## Scope

- The timeline includes trigger, step transitions, waits, decisions, actions and final outcome.
- Run/task/trace IDs connect timeline and append-only action audit.
- Authorization and redaction apply to timeline reads.

## Non-goals

Replacing immutable audit with editable UI history.

## Architecture Boundaries

Inherit [architecture alignment](../../ARCHITECTURE_ALIGNMENT.md), ADR-016 and ADR-010. Provider identifiers stay in adapters and ProviderBinding; device writes remain governed asynchronous tasks.

## Acceptance Criteria

- [ ] The timeline includes trigger, step transitions, waits, decisions, actions and final outcome.
- [ ] Run/task/trace IDs connect timeline and append-only action audit.
- [ ] Authorization and redaction apply to timeline reads.

## Demo Scenario
